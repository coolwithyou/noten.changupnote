# 구독모델로 딥분석 돌리는 법 — 운용 안내서

> 대상: 로컬에서 공고 딥분석·감사를 대량으로 돌리려는 운용자(대표님).
> 2026-08-02 채택 확정 기준. 기술 상세는 `docs/plans/2026-08-02-claude-cli-transport-for-deep-analysis.md`, 판정 근거는 `docs/research/2026-08-02-구독전환-AB-섀도-비교.md`.

## 1. 무엇이 만들어졌나 (1분 요약)

지금까지 딥분석은 매 호출마다 **Anthropic API 토큰(달러)**을 썼습니다. 이제 스위치 하나로 같은 분석을 **Claude Max 구독**(이미 결제 중인 정액제)으로 돌릴 수 있습니다.

```
                          ┌─ (기본) Anthropic API ──── 토큰 과금 · 운영 worker는 항상 이쪽
공고 → 딥분석 파이프라인 ─┤
                          └─ (스위치 ON) claude CLI ── Max 구독 소진 · 실지출 0 · 로컬 전용
```

핵심 사실 세 가지:

1. **분석 로직은 단 한 줄도 다르지 않습니다.** 같은 프롬프트, 같은 22축 스키마, 같은 검증(원문 인용 실재 확인)·게이트·승격 절차를 통과합니다. 바뀌는 건 "어느 문으로 모델을 호출하나"뿐입니다.
2. **품질은 검증됐습니다.** 채택 전 A/B 비교에서 원문 대조 판정 59건 중 구독 레인이 추출 30:3, 감사 19:1로 우세했고, 환각(원문에 없는 조건 지어내기)은 0건, 원문 인용 검증률 100%였습니다. 모델도 opus-4-8 → **opus-5**로 올라갑니다.
3. **운영에는 영향이 없습니다.** 스위치는 로컬 실험실(lab) 명령에서만 읽히고, 운영 서버·Cloud Run worker는 구조적으로 이 코드를 타지 않습니다. 스위치를 안 켜면 지금까지와 완전히 동일합니다.

레인별 경로 (현재 확정 상태):

| 레인 | 하는 일 | 경로 |
|---|---|---|
| 추출 (`lab:smoke`/`lab:batch`) | 공고 → 22축 조건 분해 | **구독 (opus-5)** |
| 블라인드 감사 (`lab:ai-audit`) | 검수 결과 재검증 → 일치 시 자동 확정 | **구독 (sonnet-5)** |
| AI 검수 (`lab:ai-review`) | 추출 결과 채점 | API 유지 (fable-5 — 캘리브레이션 결속, 전환 보류) |
| 질문 보강 (`lab:confirmations`) | 자가신고 질문 생성 | API 유지 |

검수·질문 레인에서 스위치를 켠 채 실행하면 "이 레인은 API 유지" 안내 로그가 뜹니다 — 조용히 과금되는 일은 없습니다.

## 2. 시작 전 확인 (30초)

구독 결제가 되려면 **claude CLI가 Max 계정으로 로그인돼 있어야** 합니다. 터미널에서:

```bash
claude /status        # 대화형에서 확인하거나
security find-generic-password -s "Claude Code-credentials" > /dev/null && echo "OK: Keychain 인증 있음"
```

주의 하나: 셸 환경에 `ANTHROPIC_API_KEY`가 export돼 있어도 괜찮습니다(스위치 경로는 Keychain OAuth를 씁니다). 단, **`claude --bare` 형태로는 절대 돌리지 마세요** — bare 모드는 구독 대신 API 키로 과금됩니다. 이 트랙의 코드는 bare를 쓰지 않으니, 직접 claude 명령을 개조하지 않는 한 신경 쓸 일 없습니다.

## 3. 실행 방법

모든 명령은 리포 루트(`~/noten.works/cunote`)에서 실행합니다. 스위치는 env 3개가 전부입니다:

| env | 값 | 의미 |
|---|---|---|
| `ANALYSIS_LAB_TRANSPORT` | `claude-cli` | 구독 경로 ON (미설정 = 기존 API) |
| `ANALYSIS_LAB_MODEL` | `claude-opus-5` | 추출 모델 (채택 확정값) |
| `ANALYSIS_LAB_TIMEOUT_MS` | `900000` | 타임아웃 15분 (CLI는 API보다 3~5배 느림 — 고밀도 공고가 기본 9분을 넘긴 실측 있음) |

### 3-1. 맛보기 1건 (스모크)

```bash
ANALYSIS_LAB_TRANSPORT=claude-cli ANALYSIS_LAB_MODEL=claude-opus-5 pnpm lab:smoke
```

끝나면 요약이 출력됩니다. `transport: claude-cli`와 `error: 없음`이 보이면 정상입니다.

### 3-2. 대량 배치 (본 사용법)

```bash
ANALYSIS_LAB_TIMEOUT_MS=900000 ANALYSIS_LAB_TRANSPORT=claude-cli ANALYSIS_LAB_MODEL=claude-opus-5 \
  pnpm lab:batch -- --limit=30
```

- 동시 2건씩 진행하며, 공고당 대략 3~9분(크기에 따라) 걸립니다.
- **이미 분석 완료(ok)된 공고는 자동으로 건너뜁니다** — 중간에 끊겨도 같은 명령을 다시 치면 이어서 합니다.
- 실패한 공고를 다시 돌리려면 `--retry-errors`를 붙입니다.

### 3-3. 블라인드 감사 (검수 후 자동 확정)

검수(ai-review)가 끝난 런에 대해:

```bash
ANALYSIS_LAB_TRANSPORT=claude-cli pnpm lab:ai-audit
```

감사 모델(sonnet-5)이 구독으로 돌고, 결과 파일에 `aiAuditTransport: "claude-cli"`가 남아 어느 경로로 판정했는지 추적됩니다.

### 3-4. API로 되돌리기

env를 빼면 끝입니다. `pnpm lab:smoke` 처럼 스위치 없이 실행하면 기존 API 경로 그대로입니다. 코드 롤백이 필요 없습니다.

## 4. 모니터링 — 무엇을 보면 되나

### 4-1. 실행 중: 배치 로그

터미널 로그에서 볼 것 세 가지:

- `(n/전체) 완료: [층] 공고제목 · 63s · $0.32` — 정상 진행. 달러 표시는 **명목 비용**입니다(§4-3).
- `(n/전체) error 런 저장: ...` — 그 공고만 실패로 기록되고 배치는 계속됩니다. 몇 건 있어도 정상 범위(재시도로 대부분 해소).
- `윈도 소진 감지 — 신규 착수 중단` — Max 구독의 5시간 사용량 창이 바닥난 것. 배치가 스스로 멈춥니다(§5-1).

### 4-2. 실행 후: 결과 확인

- **런 파일**: `spike-out/analysis-lab/<공고>/run-*.json` — `transport` 필드로 어느 경로였는지, `error`가 null인지 확인.
- **품질 게이트**: `pnpm lab:aggregate` — 정밀도·비용 등 게이트 5종 판정. 기존과 동일하게 작동합니다.
- **검수 화면**: dev 서버의 analysis-lab 페이지에서 런을 열어 22축 결과를 사람 눈으로 확인하는 것도 기존 그대로입니다.

### 4-3. 구독 사용량 (진짜 지갑 모니터링)

- 런 파일·로그의 `costUsd`는 **"API로 돌렸다면 얼마였을까"의 명목치**입니다. 구독 경로에서 실지출은 0이고, 이 숫자는 품질 게이트(공고당 $1 상한 등)의 잣대로만 씁니다.
- 실제로 소진되는 것은 **Max 구독의 사용량 창**(5시간 롤링 + 주간 상한)입니다. 확인 방법:
  - `/claude-dashboard:check-usage` (Claude Code 안에서) 또는 셸의 `check-ai` 별칭 — Claude/Codex 사용량 한눈에
  - claude.ai → Settings → Usage
- 감각치: 이번 검증 기준 공고 1건 추출 ≈ opus-5 수 분 분량. 30건 배치를 하루에 몰아 돌리면 5시간 창을 상당 부분 쓸 수 있습니다. 급하지 않으면 배치를 나눠 돌리는 게 여유롭습니다.

### 4-4. 이상 신호와 대응

| 신호 | 의미 | 대응 |
|---|---|---|
| error 런에 `[CLAUDE_CLI_WINDOW_EXHAUSTED]` | 구독 사용량 창 소진 | 창이 리셋된 뒤(수 시간) **같은 명령 재실행** — 미착수 공고는 자연 재개, 소진 시점에 걸린 소수만 `--retry-errors` |
| `타임아웃됐습니다(900000ms)` | 초대형 공고 | 해당 건만 `ANALYSIS_LAB_TIMEOUT_MS`를 더 올려 재시도 |
| error에 `모델 접근 불가` / 404 | CLI 로그아웃 또는 모델명 오타 | `claude /status`로 로그인 확인 |
| error에 `(claude X.Y.Z)` 버전과 함께 구조 오류 | CLI 자동 업데이트로 출력 형식 변경 | `pnpm lab:transport:test` 실행해 확인 후 보고 — 어댑터 수정 필요 신호 |
| `input_drift 스킵` | 분석 후 공고 원문이 갱신됨 | 정상 방어 동작 — 재분석 대상으로 두면 됨 |

## 5. 운용 수칙 (채택 조건 — 지켜야 하는 것)

1. **구독 경로는 로컬 dev 전용입니다.** 운영 서버·배포 환경에 `ANALYSIS_LAB_TRANSPORT`를 설정하지 않습니다(약관 경계이자 설계 경계).
2. **사람 표본 감사를 유지합니다.** 구독 감사는 자동 확정률이 높아지는 방향이라, 자동 확정된 항목의 표본 검토(기존 검수팀 절차)를 계속 돌립니다.
3. **검수 가이드 사례집이 안전판입니다.** A/B에서 발견된 추출 결함 패턴 2종(축 값 오배치, 배제 조건 연산자 반전)이 사례집에 등재돼 있어 검수 단계에서 걸러집니다 — 검수 시 exclusion 조건의 부등호 방향은 꼭 원문과 대조하세요.
