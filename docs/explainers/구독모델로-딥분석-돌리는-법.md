# 구독모델로 딥분석 돌리는 법 — 운용 안내서

> 대상: 로컬에서 공고 딥분석·감사를 대량으로 돌리려는 운용자(대표님).
> 2026-08-02 채택 확정 기준. 기술 상세는 `docs/plans/2026-08-02-claude-cli-transport-for-deep-analysis.md`, 판정 근거는 `docs/research/2026-08-02-구독전환-AB-섀도-비교.md`.

## 1. 무엇이 만들어졌나 (1분 요약)

지금까지 딥분석은 매 호출마다 **Anthropic API 토큰(달러)**을 썼습니다. 이제 스위치 하나로 같은 분석을 **Claude Max 구독**(이미 결제 중인 정액제)으로 돌릴 수 있습니다.

```
                          ┌─ (기본) Anthropic API ──── 토큰 과금 · 운영 worker는 항상 이쪽
공고 → 딥분석 파이프라인 ─┤
                          └─ (스위치 ON) claude CLI ── Max 구독 소진 · 실지출 0 · 로컬 전용
```

핵심 사실 세 가지:

1. **분석 로직은 단 한 줄도 다르지 않습니다.** 같은 프롬프트, 같은 22축 스키마, 같은 검증(원문 인용 실재 확인)·게이트·승격 절차를 통과합니다. 바뀌는 건 "어느 문으로 모델을 호출하나"뿐입니다.
2. **품질은 검증됐습니다.** 채택 전 A/B 비교에서 원문 대조 판정 59건 중 구독 레인이 추출 30:3, 감사 19:1로 우세했고, 환각(원문에 없는 조건 지어내기)은 0건, 원문 인용 검증률 100%였습니다. 모델도 opus-4-8 → **opus-5**로 올라갑니다.
3. **운영에는 영향이 없습니다.** 스위치는 로컬 실험실(lab) 명령에서만 읽히고, 운영 서버·Cloud Run worker는 구조적으로 이 코드를 타지 않습니다. 스위치를 안 켜면 지금까지와 완전히 동일합니다.

레인별 경로 (현재 확정 상태):

| 레인 | 하는 일 | 경로 |
|---|---|---|
| 추출 (`lab:smoke`/`lab:batch`) | 공고 → 22축 조건 분해 | **구독 (opus-5)** |
| 블라인드 감사 (`lab:ai-audit`) | 검수 결과 재검증 → 일치 시 자동 확정 | **구독 (sonnet-5)** |
| AI 검수 (`lab:ai-review`) | 추출 결과 채점 | **구독 (fable-5)** — 2026-08-04 전환(검증 GO: 원문 대조 41:26, `docs/research/2026-08-04-검수레인-구독전환-일치율-검증.md`) |
| 질문 보강 (`lab:confirmations`) | 자가신고 질문 생성 | **구독** — 2026-08-04 전환(동일 배선) |
| Kordoc 빠른 작성 선분석 | HWP/HWPX 입력 필드 전수 판정·미해결 재판정 | **구독 (opus-5)** — 전체 후보 처리 후 필요한 후보만 최대 2회 재판정 |

이제 네 레인 모두 `ANALYSIS_LAB_TRANSPORT=claude-cli` 스위치를 따릅니다. env 미설정이면 전부 기존 API 경로 그대로입니다(운영 무영향). 검수 실행 예: `ANALYSIS_LAB_TRANSPORT=claude-cli pnpm lab:ai-review -- --model=claude-fable-5 --limit=30` — 사이드카에 `aiReviewTransport`가 기록돼 어느 경로로 채점됐는지 남습니다.

## 2. 시작 전 확인 (30초)

구독 결제가 되려면 **claude CLI가 Max 계정으로 로그인돼 있어야** 합니다. 터미널에서:

```bash
claude /status        # 대화형에서 확인하거나
security find-generic-password -s "Claude Code-credentials" > /dev/null && echo "OK: Keychain 인증 있음"
```

주의 하나: 셸 환경에 `ANTHROPIC_API_KEY`가 export돼 있어도 괜찮습니다(스위치 경로는 Keychain OAuth를 씁니다). 단, **`claude --bare` 형태로는 절대 돌리지 마세요** — bare 모드는 구독 대신 API 키로 과금됩니다. 이 트랙의 코드는 bare를 쓰지 않으니, 직접 claude 명령을 개조하지 않는 한 신경 쓸 일 없습니다.

## 3. 실행 방법

모든 명령은 리포 루트(`~/noten.works/cunote`)에서 실행합니다. 스위치는 env 3개가 전부입니다:

| env | 값 | 의미 |
|---|---|---|
| `ANALYSIS_LAB_TRANSPORT` | `claude-cli` | 구독 경로 ON (미설정 = 기존 API) |
| `ANALYSIS_LAB_MODEL` | `claude-opus-5` | 추출 모델 (채택 확정값) |
| `ANALYSIS_LAB_TIMEOUT_MS` | `900000` | 타임아웃 15분 (CLI는 API보다 3~5배 느림 — 고밀도 공고가 기본 9분을 넘긴 실측 있음) |

### 3-1. 맛보기 1건 (스모크)

```bash
ANALYSIS_LAB_TRANSPORT=claude-cli ANALYSIS_LAB_MODEL=claude-opus-5 pnpm lab:smoke
```

끝나면 요약이 출력됩니다. `transport: claude-cli`와 `error: 없음`이 보이면 정상입니다.

### 3-2. 반복형 분석 에이전트 (권장 사용법)

신규 공고 선정부터 딥분석·Kordoc·독립 검수·감사·원인별 보정까지는 한 명령으로 실행합니다. 기본 실행은 **계획 확인만** 하므로 모델을 호출하지 않습니다.

```bash
ANALYSIS_LAB_TRANSPORT=claude-cli ANALYSIS_LAB_MODEL=claude-opus-5 \
  pnpm lab:agent -- --count=30
```

출력된 `기존 품질 보정 / 미분석 실행 / 신규 안전 후보` 수를 확인한 뒤 실제 실행을 명시합니다.

```bash
ANALYSIS_LAB_TRANSPORT=claude-cli ANALYSIS_LAB_MODEL=claude-opus-5 \
  pnpm lab:agent -- --count=30 --execute
```

에이전트는 매번 다음 순서를 지킵니다.

1. 현행 모집 대상 가운데 이전 실행의 `held/failed` 품질 그래프를 가장 먼저 복구
2. 이미 선정됐지만 아직 성공 런이 없는 공고를 이어서 분석
3. 위 두 목록이 비었을 때만 새 모집 공고를 안전 후보에서 Opus 5로 자동 선정
4. 공고별 22축 딥분석과 Kordoc 빠른 작성 선분석을 함께 실행
5. Fable 5 독립 검수 → Sonnet 5 블라인드 감사 → 충돌 항목만 Opus 5 3차 판정
6. 신청자격·Kordoc·22축 계약 중 실패 원인에 해당하는 공고만 정확한 ID로 보정하고 품질 그래프 재평가

`passed`, 안전한 `partial`, 빠른 작성 대상 문서가 없는 `not_applicable`은 종결입니다. 필수 자격이나 필수 입력을 확정하지 못한 `held/failed`만 최대 3개 교정 사이클을 돕니다. 그래도 닫히지 않으면 억지로 통과시키지 않고 `partial` 실행 보고서에 정확한 blocker를 남깁니다.

같은 명령은 반복 실행할 수 있습니다. Max 사용량 창 소진, 로컬 종료, 개별 공고 실패로 중단돼도 다음 실행은 이전 불변 런과 품질 그래프를 읽어 미완료 공고부터 재개합니다. 시간이 지나 마감·비노출된 과거 대기는 신규 공고 선정을 영구 차단하지 않으며, 새로 수집된 모집 공고는 다음 실행 때 자동 후보가 됩니다.

- 실행 보고서: `spike-out/analysis-lab/agent-runs/agent-*.json`
- 기본 상한: 30건, 교정 3사이클, 동시성 2, 명목 비용 `$65`
- API 폴백: 없음. 자식 단계의 `ANTHROPIC_API_KEY`를 비워 구독 CLI 실패가 API 과금으로 바뀌지 않게 합니다.
- 자동 승격: 없음. 에이전트는 로컬 분석 산출물과 품질 증거만 만들고 프로덕션 DB 승격은 별도 게이트로 남깁니다.

필요할 때만 `--max-cycles=1~5`, `--concurrency=1~3`, `--max-cost-usd=<명목 상한>`을 조정합니다. 여러 에이전트나 웹 배치를 동시에 실행하지 않습니다. 로컬 구독 lease와 기존 배치 가드가 중복 실행을 차단합니다.

### 3-2-1. 하위 대량 배치 (문제 격리용)

아래 명령은 에이전트가 내부에서 사용하는 딥분석·Kordoc 단계만 직접 실행해야 할 때 사용합니다.

```bash
ANALYSIS_LAB_TIMEOUT_MS=900000 ANALYSIS_LAB_TRANSPORT=claude-cli ANALYSIS_LAB_MODEL=claude-opus-5 \
  pnpm lab:batch -- --reanalyze-outdated --with-application-roundtrip \
  --roundtrip-model=claude-opus-5 --limit=30 --concurrency=2 --max-cost-usd=65
```

- 2026-08-09 현행 5건 파일럿에서 딥분석과 Kordoc를 합친 명목 예상치가 30건 `$53.26`으로 계산됐다. `$65`는 API 예산이 아니라 구독 실행의 폭주·미착수를 막는 명목 상한이다.
- 딥분석 자체는 보통 공고당 수 분이지만, Kordoc 양식 후보가 많은 공고는 15분 이상 걸릴 수 있습니다. 실제 219개 미해결 후보 재판정은 약 14분 29초였고 전체 양식 최초 판정은 더 오래 걸릴 수 있으므로 30건 배치는 충분한 시간을 두고 실행합니다.
- **이미 분석 완료(ok)된 공고는 자동으로 건너뜁니다** — 중간에 끊겨도 같은 명령을 다시 치면 이어서 합니다.
- 실패한 공고를 다시 돌리려면 `--retry-errors`를 붙입니다.
- 같은 배치에서 Kordoc도 함께 실행됩니다. 후보가 180개를 넘는 큰 양식도 구독 경로에서는 끝까지 처리하고, 누락·저신뢰 후보만 Opus 5가 최대 2회 다시 판정합니다.
- 재판정 뒤에도 모호한 필드는 억지로 확정하지 않습니다. 확정된 안전 필드만 `부분 완료`로 빠른 작성에 반영하고, 남은 필드는 문서 직접 편집으로 열어둡니다.
- 브라우저 연결이 끊겨도 서버의 기존 분석은 끝까지 계속됩니다. 같은 로컬 서버에 새 분석을 겹쳐 보내면 `local_analysis_already_running`으로 차단되므로 기존 실행 상태를 먼저 확인합니다.
- 정확한 공고만 다시 분석할 때는 `--grant-ids=<uuid,uuid,...>`를 사용합니다. 지정 ID 중 선정 대상이 아닌 값이 하나라도 있으면 실행 전에 중단합니다.

### 3-2-2. 5건에서 30건으로 넓히는 준비 게이트

처음부터 30건을 성공으로 간주하지 않습니다. 같은 배치가 실제로 처리한 정확한 공고 ID를 품질 그래프에 다시 넣어 다음 다섯 조건을 각각 확인합니다.

1. 배치가 오류·구독 창·명목 비용 가드로 끊기지 않고 정상 종결
2. 요청한 5건이 모두 시작·성공하고 중복이나 미착수 없음
3. 딥분석과 Kordoc 모두 `claude-cli/claude-opus-5` provenance
4. 딥분석 22축과 독립 AI 검수·감사 통과
5. Kordoc가 `complete/partial/not_applicable`로 안전 종결하고 필수 입력 미해결 0건

5건 실행 직후 판정:

```bash
pnpm lab:bulk-readiness -- --stage=pilot5 --write
```

후속 재분석으로 현재 `batch-job.json`이 바뀐 뒤에도 원래 5건 배치를 다시 판정하려면 보존한 불변 스냅샷을 명시합니다.

```bash
pnpm lab:bulk-readiness -- --stage=pilot5 --batch-job=<보존한-batch-job.json> --write
```

- `GO`: 30건 dry-run으로 대상 수·기간 스킵·명목 비용 상한을 확인한 뒤 실행합니다.
- `ITERATE`: 출력된 딥분석 또는 Kordoc 실패 공고만 재검수·재판정합니다. 5건 전체를 무조건 다시 돌리지 않습니다.
- `BLOCKED`: API 혼입, Kordoc 병렬 미사용, 배치 오류처럼 실행 계약이 깨진 상태입니다. 대량 실행을 시작하지 않습니다.
- `WAIT`: 배치 실행 중입니다. 실행이 끝난 뒤 같은 명령을 다시 사용합니다.

30건 실행이 끝난 뒤에는 같은 계약을 `--stage=batch30 --write`로 다시 확인합니다. 판정 JSON은 `spike-out/analysis-lab/bulk-readiness/<batch-job-id>/` 아래 불변 증거로 남습니다. 이 게이트는 제품 승격을 자동 실행하지 않으며, 분석 결과의 대량 생산 준비만 판단합니다.

### 3-3. 품질 그래프 피드백 루프

5건과 30건 배치는 다음 순서로 좁혀서 개선합니다.

1. Opus 5가 22축 딥분석과 Kordoc 빠른 작성 선분석을 공고당 병렬 실행
2. Fable 5가 추출 조건·빈 축 누락을 검수
3. Sonnet 5가 Fable 판정을 원문 기준으로 독립 감사
4. 두 모델이 충돌한 항목만 Opus 5가 3차 판정
5. `eligibility` 누락이 확정된 공고만 `lab:repair-held`로 재분석하고 최근 5개 런의 고유 교정을 누적

`ranking` 누락은 신청 가능성을 바꾸지 않으므로 전체 배치를 막지 않고, 해당 점수 신호를 미반영한 `partial`로 남긴다. Kordoc도 확정 필드를 사용할 수 있고 필수 미해결이 0건이면 `partial`을 안전 종결로 인정한다. 이 경계가 대량 분석을 막는 과도한 완벽주의와 신청자격 오판을 동시에 피한다.

### 3-4. 블라인드 감사 (검수 후 자동 확정)

검수(ai-review)가 끝난 런에 대해:

```bash
ANALYSIS_LAB_TRANSPORT=claude-cli pnpm lab:ai-audit
```

감사 모델(sonnet-5)이 구독으로 돌고, 결과 파일에 `aiAuditTransport: "claude-cli"`가 남아 어느 경로로 판정했는지 추적됩니다.

### 3-5. API로 되돌리기

env를 빼면 끝입니다. `pnpm lab:smoke` 처럼 스위치 없이 실행하면 기존 API 경로 그대로입니다. 코드 롤백이 필요 없습니다.

## 4. 모니터링 — 무엇을 보면 되나

### 4-1. 실행 중: 배치 로그

터미널 로그에서 볼 것 세 가지:

- `(n/전체) 완료: [층] 공고제목 · 63s · $0.32` — 정상 진행. 달러 표시는 **명목 비용**입니다(§4-3).
- `(n/전체) error 런 저장: ...` — 그 공고만 실패로 기록되고 배치는 계속됩니다. 몇 건 있어도 정상 범위(재시도로 대부분 해소).
- `윈도 소진 감지 — 신규 착수 중단` — Max 구독의 5시간 사용량 창이 바닥난 것. 배치가 스스로 멈춥니다(§5-1).

### 4-2. 실행 후: 결과 확인

- **런 파일**: `spike-out/analysis-lab/<공고>/run-*.json` — `transport` 필드로 어느 경로였는지, `error`가 null인지 확인.
- **품질 게이트**: `pnpm lab:aggregate` — 정밀도·비용 등 게이트 5종 판정. 기존과 동일하게 작동합니다.
- **5→30 대량 준비 게이트**: `pnpm lab:bulk-readiness -- --stage=pilot5 --write` — 해당 배치의 정확한 공고만 딥분석/Kordoc 그래프에 대조합니다. 원래 배치 파일을 보존했다면 `--batch-job=<path>`로 명시합니다.
- **검수 화면**: dev 서버의 analysis-lab 페이지에서 런을 열어 22축 결과를 사람 눈으로 확인하는 것도 기존 그대로입니다.

### 4-3. 구독 사용량 (진짜 지갑 모니터링)

- 런 파일·로그의 `costUsd`는 **"API로 돌렸다면 얼마였을까"의 명목치**입니다. 구독 경로에서 실지출은 0이고, 이 숫자는 품질 게이트(공고당 $1 상한 등)의 잣대로만 씁니다.
- 실제로 소진되는 것은 **Max 구독의 사용량 창**(5시간 롤링 + 주간 상한)입니다. 확인 방법:
  - `/claude-dashboard:check-usage` (Claude Code 안에서) 또는 셸의 `check-ai` 별칭 — Claude/Codex 사용량 한눈에
  - claude.ai → Settings → Usage
- 실측치: 현행 v12 3건 재분석은 동시성 2에서 15분 55초, 명목 `$4.5092`였다. 양식 후보 약 97개·3문서인 포항 공고는 11분 23초가 걸렸다. 30건은 5시간 창을 한 번에 소진할 수 있으므로 창 남은 사용량을 확인하고 시작한다.

### 4-4. 이상 신호와 대응

| 신호 | 의미 | 대응 |
|---|---|---|
| error 런에 `[CLAUDE_CLI_WINDOW_EXHAUSTED]` | 구독 사용량 창 소진 | 창이 리셋된 뒤(수 시간) **같은 명령 재실행** — 미착수 공고는 자연 재개, 소진 시점에 걸린 소수만 `--retry-errors` |
| `타임아웃됐습니다(900000ms)` | 초대형 공고 | 해당 건만 `ANALYSIS_LAB_TIMEOUT_MS`를 더 올려 재시도 |
| error에 `모델 접근 불가` / 404 | CLI 로그아웃 또는 모델명 오타 | `claude /status`로 로그인 확인 |
| error에 `(claude X.Y.Z)` 버전과 함께 구조 오류 | CLI 자동 업데이트로 출력 형식 변경 | `pnpm lab:transport:test` 실행해 확인 후 보고 — 어댑터 수정 필요 신호 |
| `input_drift 스킵` | 분석 후 공고 원문이 갱신됨 | 정상 방어 동작 — 재분석 대상으로 두면 됨 |

## 5. 운용 수칙 (채택 조건 — 지켜야 하는 것)

1. **구독 경로는 로컬 dev 전용입니다.** 운영 서버·배포 환경에 `ANALYSIS_LAB_TRANSPORT`를 설정하지 않습니다(약관 경계이자 설계 경계).
2. **사람 표본 감사를 유지합니다.** 구독 감사는 자동 확정률이 높아지는 방향이라, 자동 확정된 항목의 표본 검토(기존 검수팀 절차)를 계속 돌립니다.
3. **검수 가이드 사례집이 안전판입니다.** A/B에서 발견된 추출 결함 패턴 2종(축 값 오배치, 배제 조건 연산자 반전)이 사례집에 등재돼 있어 검수 단계에서 걸러집니다 — 검수 시 exclusion 조건의 부등호 방향은 꼭 원문과 대조하세요.
