# 실제 사업자 추천 0건 원인 진단

관측: 2026-09-24 19:52:59 KST. 운영 DB에 읽기 전용 연결을 강제하고, 실제 회사의 저장 프로필·현재 원천 정책·제품과 같은 공고 조회 옵션·현재 질문 결속을 사용해 matcher를 실행했다. 코드·운영 데이터 변경, 모델 호출, 유료 사업자 조회는 하지 않았다.

## 결론

현재 추천 0건은 해당 회사에 실제로 맞는 공고가 없다는 증거가 아니다. 매칭에 사용할 수 있는 분석·발행 재고가 작고, 그 안에서도 미해석 조건과 검수 상태가 최종 추천을 막는다. 실제 적합 공고 수는 원문 판정 없이 확정할 수 없다.

| 구분 | 건수 |
| --- | ---: |
| 제품 조회 대상 | 1,514 |
| 접수중 / 예정 / 상태 미확정 | 541 / 19 / 954 |
| 탐색 전용 discovery | 1,450 |
| 현재 매칭 근거 사용 가능 verified | 64 |
| verified 중 현재 회사 조건 불충족 판정 | 27 |
| verified 중 조건부·미해결 판정 | 37 |
| 최종 추천 가능 | 0 |

verified 64건은 모두 접수중이며 접수중 541건의 11.8%다. verified는 현재 출처에 결속된 분석을 사용할 수 있다는 의미이고 모든 자격조건이 해석·검수 완료됐다는 뜻은 아니다. discovery는 matcher가 회사 조건을 비교하지 않고 conditional/needs_core_review를 반환한다. 따라서 conditional 1,487건을 실제 적합 후보 수로 표현하면 안 된다.

## 단계별 병목

1. discovery 1,450건: 미검수·미승격 사유 1,409건, 원문 변경으로 이전 분석을 쓸 수 없는 경우 41건. 미검수 1,409건 중 339건에는 저장된 criterion이 있지만 현재 승인된 매칭 근거로 사용되지 않는다. DB의 analysis_lab_deep payload는 이 집합에서 0건이다. 이는 로컬 파일에 존재할 수 있는 미발행 분석까지 부재하다는 뜻은 아니다.
2. verified 64건: manifest partial 63건, reviewed 1건. 유일한 reviewed 공고는 대구 본사 요건으로 현재 서울 회사가 탈락한다.
3. 조건부 37건: 26건은 핵심 조건 미해석, 11건은 required/exclusion 검수 미완료가 현재 우선 차단 사유다. 37건 모두 manifest partial이다. 추가 회사 정보 부족도 겹쳐 있으므로 원문 조건 해석만으로 전부 추천된다고 보장하지 않는다.
4. 현행 matcher는 core unknown·needs_review를 검사하고, 이후에도 manifest partial/unstructured면 추천을 보류한다. 사용자 정보 보충만으로 이 공급 측 미완료 상태를 해소할 수 없다. 같은 분석을 재실행하기보다 미완료 조건을 해석·검수·질문 발행으로 종결하는 경로를 확인해야 한다.

조건 불충족 판정 27건과 not_recommended 표시 17건은 다른 집계다. 10건은 검수 gate가 먼저 표시되어 needs_core_review에 포함된다. 상호배타 원인 표에는 eligibility를 사용하고, UI tier를 더해 합계를 만들지 않는다.

## 실제 사례

- [인도 BTS 전시회](https://www.bizinfo.go.kr/sii/siia/selectSIIA200Detail.do?pblancId=PBLN_000000000126455): 공식 공고는 과학기술·ICT 중소기업을 대상으로 9월 30일까지 접수한다. 서비스의 업종 조건은 text_only로 남아 core_dimension_unknown이다. 소프트웨어 사업자를 검토할 합리적 이유는 있지만 중소기업 여부와 다른 신청요건 확인 전 적합을 확정하지 않는다.
- [Bay7 참여팀](https://www.k-startup.go.kr/web/contents/bizpbanc-ongoing.do?schM=view&pbancSn=179302): 현재 matcher에서 개인사업자 대상 조건은 통과하지만 공간·프로그램 참여 조건이 미검수로 남았다. 공식 원문에는 대전 입주공간과 별도 업력 분류도 있어, 대상 유형 통과만으로 적합 처리할 수 없다.
- 수산물 판매·특정 지역 제조업 등 전문 분야 공고도 조건을 해석하지 못하면 conditional에 남는다. 따라서 37건 역시 수작업 원문 판정 전에는 유효 후보군으로 부풀려 말하지 않는다.

## 다음 검증의 기준

현재 접수중인 서울·전국 초기 소프트웨어 사업자 관련 공고를 먼저 원문으로 대조해 적합/부적합/회사 답변 필요를 확정한다. 같은 집합의 서비스 판정과 비교해 누락이 수집·분석·발행·조건 해석·확인 질문 중 어디서 발생하는지 기록한다. 추천 수가 0이라는 사실 대신, 실제 적합한 공고를 얼마나 놓쳤는지를 출시 판단 지표로 사용한다. 공고 수만 늘리거나 모든 partial을 추천으로 바꾸는 것으로 대체하지 않는다.
