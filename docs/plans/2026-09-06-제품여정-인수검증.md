pnpm report:product-readiness --source=database

2026-09-06 16:19 KST의 DB 읽기: 활성·노출 재고 **1,444**, 매칭 공급 **92**, 차집합 **1,352**.
저장소의 활성/노출/dedup/승격 판정을 재사용한 수치이지 전체 역사 공고 또는 전 국민 수혜 가능 수가 아니다.
두 조회 사이에 집합이 바뀌면 재시도가 필요하며 DB 원자 snapshot을 제공하는 보고서는 아니다.
공급 차집합은 곧 분석 실패 건수가 아니다. 작성 metadata는 미확인 44, 초안 신호 12,
웹폼 신호 36이며 실제 RHWP 가용성은 이 집계만으로 판정하지 않는다.

## 아직 필요한 인수

1. 실제 로그인 공급자·브라우저·객체 저장소를 포함한 격리 테스트 환경과 지정 계정을 확정한다.
   임시 PostgreSQL 경쟁/rollback/RLS는 통과했으나 OAuth 세션 인수를 대체하지 않는다.
2. 저장 → 로그아웃 → 재로그인 → 회사 전환 → 재조회, 실제 기관 HWP/HWPX에서 사용자 적용 →
   서버 저장 → 새 탭 재개 → 브라우저 다운로드를 검증한다. 이번 실제 엔진/DB 검증은 합성 양식과
   메모리 객체 저장소를 사용했으며 외부 R2·사용자 서명/증빙·최종 제출을 실행하지 않았다.
3. 원천 정정 정책은 2026-09-07 사용자 승인으로 확정되어 업무 구현으로 이어졌다.
   [정정 정책과 격리 인수](2026-09-07-원천정정-정책과-격리인수.md)에 따라 실제 계정·관리자 화면을 인수한다.
4. 검증된 소스의 운영 반영 범위를 승인받아 migration 0078/0079/0080, 배포, 계측 설정을 적용하고
   인증된 live smoke를 수행한다. 앞선 개선은 `64481b1`로 커밋했으며 이번 정정 후속은 미커밋이다.
   push·운영 migration·배포는 하지 않았다.

원천 정정은 **공식 원천값 보존 + 사용자 설명 별도 관리 + 관리자 검수**로 확정되었다.
공식 원천 갱신과 원문에 근거한 내부 수집·해석 오류 수정을 구분한다. 사용자 증빙만으로 공식
값을 덮어쓰지 않으며, 구현 상태와 실제 운영 인수 완료는 별도로 기록한다.

## 추가된 격리 검증과 관측 활성화

```sh
# initdb/postgres/pg_ctl이 있는 환경. 기존 접속 환경을 버리고 새 전용 Unix cluster만 사용한다.
pnpm test:product-postgres
# 빈 페이지에서 실제 IntersectionObserver 검증. 외부 전송 없음. agent-browser 필요.
node tools/test-product-exposure-browser.mjs
```

PostgreSQL 18.4에서 80개 migration을 전부 적용했다. SQL 정책이 실제 적용되는 non-superuser/
NOBYPASSRLS 회사 경로와, 기존 서버의 privileged 연결 + 검증된 회사 문맥 문서 경로를 나눠 검증했다.
매회 cluster는 정지되고 생성한 테스트 자료만 `/tmp/cunote-product-pg-*`에 보존된다.
`0079_snapshot.json`은 공식 Drizzle generate로 생성했고 임의 snapshot 복제를 하지 않았다.

계측은 기본 비활성이다. 운영 migration 후 `CUNOTE_PRODUCT_EXPOSURE_ENABLED=true`, 기존
`NEXTAUTH_SECRET`/`AUTH_SECRET` 32자 이상, 서버 DB 역할의 새 테이블 쓰기 권한을 확인해야 한다.
활성화 뒤 DB 보고서는 **계측 이후 인증된 매칭 카드의 최초 신호 수신 지연**을 반환한다.
기준은 최신 유효 승격의 실제 criterion snapshot 일치, 회사/사용자/승격 item 서명, 15분 만료다.
카드가 뷰포트에 50% 이상 500ms 들어온 뒤에만 전송하며, 기록은 승격별 한 행·append-only다.
신원/입력값은 DB 노출 원장에 저장하지 않는다. 신호 유실·차단·네트워크 지연이 있으므로 과거
최초 노출/전체 사용자/실제 열람을 의미하지 않는다. 운영 자료의 이전 노출 시각을 소급 생성하지 않는다.

공용 분석/승격 증거/작성 근거의 전이 runtime import가 실험실에 도달하지 않도록 검사한다.
역사 import 호환·receipt identity는 유지하며 이동 함수 179개 본문을 원본과 대조했다.
실험실의 로컬 파일 읽기·실행 권한·로컬 preview와 역사 타입은 의도적으로 남아 있다.

## 검증 영수증

로컬 worktree의 최종 `pnpm test`는 exit 0으로 통과했다. 패키지 build·웹/관리자 typecheck,
프로필/제품 여정·작성/문서 에이전트·권한 및 기존 집계 gate를 포함한다.
`pnpm test:matching-unit`, `pnpm verify:profile-product-paths`도 exit 0으로 통과했다.
문서 변경 후 `git diff --check` 통과. 임시 로그는 영구 CI 영수증이 아니며 원격 CI는 실행하지 않았다.

기존 화면 브라우저 검증은 실행 중이던 4010 서버를 사용했다. 회사 이름/명시적 URL/버전 전송/충돌 시 편집 유지는
합성 API 응답으로 확인했다. 추가 DB/실제 바이트 검증은 위 격리 환경에서 수행했으며, 실제 OAuth와
서비스 R2/브라우저 다운로드 인수는 수행하지 않았다. 노출 관측 추가 뒤 실제 결과 화면의 시각 QA는 미수행이다.

DB 구현은 [Postgres 잠금 문서](https://www.postgresql.org/docs/current/explicit-locking.html)와
[Drizzle 조회 문서](https://orm.drizzle.team/docs/select)를 확인해 기존 프로젝트 방식으로 구현했다.
원천 정정·역사 실험의 실행 권한은 [AGENTS.md](../../AGENTS.md)를 따른다.
