## GO / STOP 기준

GO:

- exact SHA의 preview build가 성공한다.
- 1,508건 모집단·dashboard·pagination 고유 ID 합계가 일치하고 중복이 없다.
- verified는 기존 판단 경로를 유지하고 discovery는 원문 확인 상태로만 보인다.
- discovery에 숫자 점수, 확인되지 않은 조건·혜택·작성 지원이 생기지 않는다.
- 목록·상세 요청에서 모델 호출이 0이다.

STOP 및 복구:

- 기존 verified 공고 손실, discovery 자동 적격/탈락, 비공개·마감·중복 위반,
  지속적 5xx가 발생하면 전환을 중단한다.
- 복구는 `MATCH_DISCOVERY_CANDIDATES_ENABLED=false`를 적용한 배포로 discovery 경로를 끈다.
  Vercel 환경변수 수정만으로 기존 배포가 즉시 바뀌지는 않는다. 긴급 복구에는 기존 정상 배포를 사용한다.
  이 기능은 새 서비스 데이터를 쓰지 않으므로 DB rollback은 필요 없다.
- 단일 discovery 표시 결함이나 남은 검수 경고만으로 전체를 되돌리지 않는다.

사용자가 직전 제안의 다음 범위를 승인했다. 같은 범위에서 커밋이나 배포 ID가 바뀌어도
재승인을 추가하지 않는다.

1. 로컬 14개 커밋을 `origin/main`에 push
2. preview 배포와 preview 환경의 flag 설정
3. verified/discovery/명확한 불일치 각 1건 preview 제한 인수

배포 담당은 `gpt-5.6-sol/high`, 제한 인수 담당은 `gpt-5.6-sol/high`,
총괄·의미 판단은 `gpt-6-astra` 현재 세션이다. 필요한 쟁점만 총괄로 전달한다.
production 환경변수 변경·배포·alias 전환은 이번 승인에 포함되지 않는다.
main push가 production 자동 배포를 유발하는지 먼저 확인하고, 연결된 경우 preview를
먼저 준비한 뒤 해당 영향 범위를 보고한다.

이 승인은 기존 공고 DB의 일괄 promotion, exact19 재실행, 운영 모델 활성화 권한으로
확대하지 않는다.

## P5 preview 인수에서 확인한 수정 사항

Vercel Git 연결은 `main`을 production branch로 자동 배포한다. production 배포 승인을
추정하지 않고 동일 소스를 `p5/discovery-preview-20260919`에 올려 preview로 검증했다.
첫 READY preview 소스는 `8e3e27309dbd8a332f9219178edf46c950aab5e4`, deployment는
`dpl_BjyRr7dbP92tRPeC62EiXcGErYEC`다. 접근 보호를 유지하고 기존 가상기업 경로로 인수한다.

기존 순수 core 집계만으로는 발견되지 않았던 제품 연결 문제를 실제 경로에서 확인했다.

| 문제 | 관측 | 필요한 수정 |
| --- | --- | --- |
| 전체 접근 누락 | 대시보드는 첫 40건만 펼치고 다음 API 페이지를 요청하지 않음 | 기존 cursor API에 더 보기 연결 |
| 원문 확인 후보 누락 | `/matches?biz=0000000001`에서 후보가 있는데 빈 결과 표시 | 웹 응답의 검토 버킷에서 `needs_core_review` 보존 |
| 상세 판정 재추정 | core `needs_core_review`인 verified 공고 상세에 `답하면 확정` 표시 | 엔진 판정을 ApplySheet에 전달하고 상세에서 우선 사용 |

추가로 미확인·예정 공고를 `모집 중`이라고 단정하던 카드 문구를 중립적으로 수정했다.
가상기업 discovery 상세의 CTA 설명도 실제 행동인 원문 확인에 맞춘다.
이 범위를 한 묶음으로 수정하고 관련 회귀와 최종 preview 인수만 수행한다.
일반 로그인 회사의 페이지네이션 브라우저 인수는 실제 인증 세션 확보 전에는 완료로 표기하지 않는다.
