# 작성 중심 1차 구현 인수 — 실행 대기

이 문서는 실사용 완료 보고가 아니다. 구현 정본은
[상세 계획](2026-09-30-authoring-first-implementation.md), 현재 증거는
[진행 기록](../../PROGRESS-authoring-first.md)이다. 작업 브랜치는 `coolwithyou/authoring-first`다.

## 실행 전제

- 현재 4010/4011에 사용자 실행 서버가 없다. `AGENTS.md`에 따라 개발 서버를 임의로 시작하지 않는다.
- 이번 변경은 migration 0094~0098을 포함한다. 실제 회사가 없는 별도 테스트 DB에 적용한 환경과
  테스트 회사/로그인이 필요하다. 운영 DB에 합성 fixture를 넣지 않는다.
- 첫 화면 인수는 모델 호출 0회, 유료 기업정보 조회 0회로 진행한다. 문항 AI 플래그는 기본 false다.
  모델 품질 인수는 실행 환경·자료·모델·호출 상한을 결속한 뒤 별도 실행 범위로 잡는다.
- PDF는 별도 서버 보관 키와 객체 저장소가 없으면 비활성이다. 그 상태에서도 텍스트 자료와
  문안 보관을 검증할 수 있다. 합성 메모리 저장소 PASS를 실제 R2 증거로 취급하지 않는다.

## 합성 자료로 먼저 확인할 화면 경로

| 사례 | 행동 | 기대 결과 |
|---|---|---|
| 매칭 독립 진입 | discovery/조건 미확인 공고에서 HWP/HWPX 양식을 선택 | 회사 권한 확인 후 작성 화면 진입, 적격 확정을 약속하지 않음 |
| 준비 요청 | 변환 대기가 있는 공고를 열고 버튼 클릭 전후 관찰 | 열기만으로 POST 없음, 클릭 시에만 처리 요청·결과 표시 |
| 자료 | 합성 회사 소개와 이번 사업 설명 저장 후 새로고침 | 저장값·선택 자료 복원, 미입력 항목 허용 |
| 두 신청 재사용 | 회사 공통 자료와 신청 전용 자료를 각각 등록 | 공통 자료만 다른 신청에서 선택 가능 |
| 회사 전환 | 같은 사용자로 다른 회사 선택 후 직접 API 요청 | 기존 회사 자료·문안 조회/쓰기 거절 |
| 문항 위치 누락 | 물리 입력 위치 없는 서술 문항의 문안 저장·복사 | 입력 위치 오류로 보관이 막히지 않음, 양식 반영 완료로 표시하지 않음 |
| 두 탭 충돌 | 같은 revision에서 서로 다른 문안 저장 | 한 요청만 성공, 다른 탭의 입력 유지 및 비교/재저장 가능 |
| 화면 이동 | 미저장 자료/문안이 있는 상태에서 내부 링크 클릭 | 이동을 막고 먼저 저장하도록 안내; 저장 후 이동 가능 |
| 브라우저 이동 | 탭 종료/새로고침/뒤로가기/앞으로가기 | 실제 동작 확인 필요; beforeunload와 내부 링크 보호가 모든 router 이동을 보장하지 않음 |
| 점검 | 사업명 불일치 및 총사업비/지원금/자부담 불일치 입력 | 저장된 문안에서만 검토 안내, 자동 수정·전체 문서 정확성 확정 없음 |
| 제외 조회 | 저장된 회사의 ‘제외된 공고 보기’를 열고 다음 페이지 조회 | 추천 8건 밖의 활성 공고도 이유·원문 근거·기준 시각과 함께 표시, 마감 제외 |
| 복원 | 제외 공고 복원→새로고침→취소 | 회사별 ‘다시 살펴볼 공고’에 유지, 불일치 판정 유지, 취소 후 제외 목록으로 복귀 |
| 복원 충돌 | 두 탭에서 같은 버전 변경 또는 마감 후 복원 | 한 버전만 저장, 충돌/마감 안내 후 재조회, 회사 전환 시 이전 응답 표시 안 함 |
| 원본 | 저장한 HWP/HWPX를 내려받아 대상 한글 프로그램에서 열기 | 고정 문구·표·입력 내용 유지. 다운로드 성공과 제출 완료를 구분 |

## 양식 증거별 현황

| 양식 | 이번 구현의 증거 | 남은 확인 |
|---|---|---|
| 안전관리 우수연구실 인증제 HWPX (`PBLN_000000000119234`) | 기존 native marker 편집/격리 DB 왕복 PASS | 서술 문항 작성·브라우저·외부 한글 |
| 신청자료 서식 HWP (`PBLN_000000000120959`) | 기존 native marker 편집/격리 DB 왕복 PASS | 서술 문항 작성·브라우저·외부 한글 |
| 바이오스타 2.0 사업계획서 HWPX (`PBLN_000000000123505`) | 긴 표 문항 입력 후 넘침 재현. 자동 저장 거절·이전 원본 보존 PASS | 페이지 분할 해결 또는 검증된 수동 작성 경로. 3문항 파일 왕복은 실패 상태 유지 |

후속 로컬 실험에서는 대상 표의 ‘글자처럼 취급’을 해제하고 같은 3문항을 입력하면 6쪽으로
나뉘며 native export/reopen·문구 보존·용지 경계 검증을 통과했다. 이는 원본 속성 보존 경로의
실패를 대체하지 않는다. `spike-out/authoring-first/narrative-flow-roundtrip.hwpx`를 실제 Studio와
외부 한글에서 열어 배치, 선택적 적용과 Undo를 확인해야 한다. 상세 재현·SHA는 진행 기록에 있다.

양식들은 엔진 회귀 자료다. 현재 접수 가능한 공고인지 이번 인수 준비에서 조회하지 않았으며
현재 지원 후보로 표시하지 않는다. 모든 양식의 원본 SHA와 경로는 integration fixture 상수에 있다.

## 실사용 판단에 필요한 별도 증거

1. 참여자 5명에게 사용 허락을 받은 회사 자료와 실제 작성 과제를 확보한다. 아직 참여자/자료 없음.
2. 기존 방식과 창업노트를 교차 순서로 비교한다. 초안 생성 시간이 아닌 검토·수정·사용 가능한
   파일 확보까지의 active time/wall time, 운영자 개입, 사실·양식 오류를 각각 기록한다.
3. 사용 가능한 파일까지 시간 중앙값 50% 절감과 5명 중 3명의 반복 사용/구체 가격의 유료 시험
   참여를 목표로 관측한다. 이는 현재 성과가 아니며 미확보 데이터를 합성 결과로 채우지 않는다.
4. 첫 파일 경로가 해결되기 전 신규 유료 데이터 공급자·미등록 공고 수집·독립 양식 프로젝트를
   확대하지 않는다. 어떤 회사 정보가 반복 입력을 줄이는지는 이 관측 후 우선순위를 정한다.

## 아직 끝나지 않은 구현/인수

- RHWP 표 페이지 분할, 실제 Studio rollback·원본 저장·다운로드·외부 재열기.
- 프로그램 이동/브라우저 history까지 포함하는 미저장 입력 인수.
- 실제 모델 초안 품질과 주어진 사실/계획의 의미 보존.
- 전체 양식 파일의 의미 일관성. 현재 점검은 보관 문안의 명시적 항목에 한정된다.
- 제외 후보 전체 조회·사용자 복원 저장의 실제 브라우저 인수와 검수 복합식 serving 공급. 조회·복원 코드/CAS/RLS는 격리 DB 검증을 통과했다.
- 신규 기업정보원 확대는 파일럿 필요 정보·동의·상품·비용 확인 후 결정한다.
- 실제 R2/Vercel PDF 경로, 암호 키 운용, 미참조 암호문 회수 및 보관/삭제 정책.

운영 배포·DB migration·main push·실제 모델 실행·외부 사용자 모집은 이 문서를 작성했다고
실행한 것이 아니다. 합성 검증과 제품 사용성 판단을 구분한다.
