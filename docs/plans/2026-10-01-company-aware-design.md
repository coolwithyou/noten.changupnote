# 사업자 정보 기반 공고 이해와 작성 화면 개선

기준: 2026-10-01, authoring-first HEAD 0f8c434. 사용자 목표는 검수한 시안의 문제를 개선하고
완성된 화면을 구현하는 것이다. 핵심 경험은 **내 사업자 정보로 이 공고를 대조하고 있다**는 이해다.
현재 Claude 세션 480ab212는 디자인 반영 후 입력 대기이며 중복 실행하지 않는다.

## 화면 원칙

- 회사 이름·현재 선택 회사·대조에 사용한 실제 값·출처·기준일을 보여준다. 없는 값은 미확인,
  partial은 일부 확인, 원천 분쟁은 확인 필요로 표시한다. 정확성을 암시하는 새 확률·점수는 만들지 않는다.
- 공고 조건 ↔ 내 사업자 값 ↔ 판정/남은 행동을 연결한다. 회사 정보 부족과 공고 분석 부족을 분리한다.
- 첫 탐색에서 회사 입력 패널을 자동으로 열지 않는다. 공고 목록 우선, 추가 질문은 펼침 가능한 보조 행동.
- 익명 정보는 임시이며 로그인 회사 정보와 혼동하지 않는다. 기존 저장/로그인 handoff·회사 권한을 보존한다.
- 작성 기능·자격·문서 저장을 분리한다. 조건 미확정이어도 기존 capability 범위에서 문서를 작성한다.
- 원본 양식과 문항 작성은 함께 보여준다. 자료/점검은 보조. 문안 저장·양식 반영·파일 저장의 차이는
  분명히 표시하고 실제 연결 가능한 경우만 반영한다. 기존 revision, 충돌, Undo, dirty guard는 보존한다.
- 신청 관리는 최근 저장과 다음 행동 우선. 마감 저장본도 열고 내보낼 수 있으며 흐리게 비활성처럼 보이지 않는다.
- 토큰/설치된 shadcn 재사용. 새 전체 디자인 시스템/DB/공유 DTO/판정 엔진 변경은 하지 않는다.

## 검증 경계와 변경 관리

현재 사용자 서버 4010은 main의 이전 소스다. 임의로 중단/교체하거나 장기 dev 서버를 띄우지 않는다.
이번 UI는 현재 소스의 실제 React 컴포넌트를 번들한 제한된 브라우저 fixture에서 확인한다. 이를 로그인된
운영 DB·R2·유료 AI 실행 또는 운영 배포 완료로 주장하지 않는다. 운영 배포는 별도 승인 대상이다.
본 작업은 clean authoring-first에서 검증 가능한 단위마다 한국어 커밋한다. 원래 main dirty 파일은 보존한다.

## 화면 인수 사례

1. 이름과 정보가 있는 회사: 지역/업종/업력 등 현재 값과 출처를 읽고 공고의 비교 조건을 찾는다.
2. 값이 부족하거나 출처 충돌: 미확인/일부 확인 상태가 충족처럼 보이지 않는다.
3. verified 후보 0개: 서비스가 분석하지 못한 이유와 원문 확인 행동은 보이지만 회사 부적격처럼 말하지 않는다.
4. 조건 fail: 불일치와 근거를 보여주고 보존된 작성본 접근은 유지한다.
5. 회사 전환: 회사 A의 값·답변·초안이 회사 B에 남지 않는다. 기존 keyed/권한 경계 유지.
6. 문안 저장 후 미반영: 문안 저장 상태와 파일 저장 상태를 구별하고 안전한 반영 또는 복사를 선택한다.
7. 늦은 응답/409/저장 실패: 입력을 보존하고 다음 행동을 안내한다. 최종 파일 저장을 거짓 성공으로 표시하지 않는다.
8. 360/390/1440px: 핵심 값·판정·행동이 잘리지 않으며 긴 제목·unknown·empty·viewer도 확인한다.

## Claude 시안 검수와 권장안

검수 기준은 Claude Code 세션 `480ab212-56bb-4a95-a4b4-d7505fde17d2`의 디자인 2차 반영과
로컬 미러 `docs/design/2026-09-30-workbench-claude-design-r2`이다. 구현 시작 기준은 `0f8c434`.
시안의 민트 강조, 중립 표면, 공고·작성·신청 관리의 분리는 유지한다.

| 문제 | 실제 영향 | 권장 구조 |
|---|---|---|
| 사업자 대조의 근거가 첫 화면에서 보이지 않음 | 일반 공고 목록처럼 보이며 개인화의 이유를 알기 어려움 | 회사명/기준일 + 실제 값/출처 + 공고 조건 대조를 가까이 배치 |
| 정보 입력 패널 자동 열림과 큰 질문 카드 | 공고를 보기 전에 보완 작업을 요구함 | 목록 먼저, 정보 보완은 명시 클릭과 접힘 질문으로 제공 |
| 상세 조건이 기본 닫힘 | 판단의 근거를 찾아야 함 | 조건 대조는 기본 펼침, 회사 정보 상세는 접힘으로 높이 절약 |
| 문안 편집 Sheet와 원본 분리 | 문항과 입력 위치를 함께 보기 어려움 | 데스크톱 병렬, 모바일 동일 인스턴스 유지하며 전환 |
| 문안 저장와 파일 저장의 경계 모호 | 문안을 저장한 것만으로 제출 파일이 바뀌었다고 오해 | 문안 보관/양식 반영/파일 저장의 실제 상태·행동을 구분 |
| 신청 카드의 동일 비중 3열과 마감 흐림 | 다음 행동이 묻히고 마감 저장본을 못 쓰는 것처럼 보임 | 다음 작업/최근 저장/복귀 버튼 우선, 자격·기능은 보조 펼침 |

개인화의 신뢰는 새로운 점수·확률이나 단정적 문구보다 **실제 회사 값과 원문 조건의 연결**로
만든다. 미확인·일부 확인·출처 충돌과 작성 가능 여부는 독립적으로 유지한다.
