## 주의 / 함정 (이 세션에서 실측된 것)

1. **`APPLICATION_ROUNDTRIP_EFFORT=medium`을 절대 빼먹지 말 것** — lab:batch는 Kordoc을 플래그와 무관하게 **항상** 딥분석과 함께 실행한다(형제 실행 불변식). 누락 시 Kordoc이 기본 effort로 돌아 배치가 2~3배 느려진다.
2. **`--concurrency=4` 유지** — 전역 `claude -p` 상한이 4라 인플라이트를 늘려도 처리량은 같고 건당 완료만 3배 느려진다(08-11 실측).
3. **장시간 배치는 로컬 중단에 취약** — 08-12 canary가 머신 절전/세션 종료로 killed됐다. 터미널에서 직접 실행하거나 재개를 전제할 것. 배치는 체크포인트-재개 가능: **같은 명령 재실행이면 완료분은 자동 스킵되고 이어서 돈다.**
4. 웹 배치(`/dev/analysis-lab` 배치 운영 탭)와 CLI 배치를 **동시에 실행 금지**. 다른 codex/claude 세션의 lab 명령과도 겹치지 말 것.
5. `ANALYSIS_LAB_TIMEOUT_MS=900000` 필수 — 기본 540s는 큐 대기 포함이라 대량 request_timeout 위험.
6. **P1 publisher 보호는 완료** — `c79e2c0`에서 publisher 가드·수동 CLI 락·재판별을 구현했고 `verify:promotion-protection`이 test 체인에 배선돼 있다. P1 부재를 이유로 한 전면 금지는 해제됐지만 release·write·confirm·품질 게이트는 유지한다.
7. 배치 요약의 비용은 명목값(API 환산)이다 — 구독 경로 실지출 0. 그러나 `--max-cost-usd`는 폭주 방지 상한이므로 확대에서 $30→$46.1704로 초과한 현행 동시 실행 가드를 다음 배치 전에 보정해야 한다.
