# 로컬 실제 로그인 인수

2026-09-08. 상태: **격리 환경·실제 로그인/회사 목록 scope 기반 검증 통과**.
이 문서는 로그인 기반 단위의 증거다. 후속 [확인답변 격리 인수](2026-09-08-확인답변-격리인수.md)에서
공고별 저장·409·질문 개정/철회의 실제 HTTP·DB 검증도 통과했으나 자연 UI 전체 인수 완료는 아니다.

## 승인과 선택

사용자는 현재 시스템이 개발 단계임을 밝히고 운영 배포 또는 가상 테스트환경 생성을 자율에 맡겼다.
이 승인은 환경 준비 대기를 해소한다. 기존 지정 sol/xhigh가 구현하고 root가 설계 피드백과
독립 감사를 맡는다. 이번 단위는 가장 작은 **로컬 전용 PostgreSQL + 실제 Credentials 로그인**을
선택했다. 원격 배포를 반드시 해야 한다는 뜻으로 해석하지 않는다.

Vercel 저장소 토큰으로 `noten-dev`, `NOTEN/changupnote`(Root Directory `apps/web`),
`NOTEN/changupnote-ops`(`apps/admin`) 접근은 다시 확인했다. 프로젝트·DNS·원격 환경은 변경하지 않았다.
기존 개발 서버 4010을 사용하거나 운영 DB에 합성 fixture를 넣지 않는다.

## 인수 유형 구분

이 경로는 제품에 이미 있는 비밀번호 검증·CSRF·세션·권한·실제 HTTP handler를 사용한다.
mock 사용자, 세션 cookie 위조, API 응답 대체로 로그인이나 저장을 우회하지 않는다.
지정 이메일을 로컬 합성 사용자로 seed하는 것은 실제 이메일 소유권·Google 계정 인증을
증명하지 않는다. 비밀번호는 실행마다 생성하며 외부 계정의 비밀번호를 설정·변경하지 않는다.

- 로컬 웹: `sw@noten.im`은 합성 A·B owner, `dev@noten.im`은 A editor,
  `guest@noten.im`은 A viewer.
- 로컬 관리자: `manager@noten.im`은 별도 관리자 인증/권한 원장의 합성 검수자.
- 필수 검증: 로그인·로그아웃·재로그인, 회사별 답변 격리, 저장/재조회, viewer·오소속 거부,
  오래된 답변 revision의 409, 인증 세션과 DB 결과 일치.
- 별도 미검증: Google OAuth/실제 계정 소유자 인수, 외부 R2, 기관 양식 다운로드,
  외부 호스트 배포·운영 smoke. 이 로컬 결과를 위 항목의 통과로 표현하지 않는다.

기존 [원천 정정·격리 인수](2026-09-07-원천정정-정책과-격리인수.md)의 원격 UAT 설정 검사는
변경하지 않는다. R2/OAuth가 필요 없는 이번 로컬 profile을 위해 원격 안전 조건을 완화하지 않는다.
required other/text_only가 준비도 gate 때문에 자연 UI에 노출되지 않으면 그 한계를 기록한다.
직접 API 검증을 해당 자연 UI 인수의 대체 증거로 쓰지 않는다.

## 안전·수명주기 계약

1. 새 임시 디렉터리와 빈 PostgreSQL cluster만 사용한다. DB는 Unix socket만 열고 TCP는 거부한다.
2. 소스 복사본에서 `.env*`, `.vercel`, `.git`, 기존 build 결과와 실데이터를 제외한다.
   원본 소스·사용자 `next-env.d.ts`·기존 서버는 보존한다. 복사본의 패키지 참조도 확인한다.
3. 자식 환경을 제한한다. 외부 모델·결제·발송·worker·기존 DB/스토리지 자격증명을 전달하지 않는다.
4. 실제 auth의 production 정책을 유지하고 loopback의 bounded `next start`만 실행한다.
   장기 개발 서버는 시작하지 않는다. 성공·실패 모두 서버와 전용 DB를 종료한다.
5. 로컬 비밀번호/세션 secret은 로그·명령 인자·커밋에 남기지 않는다. 임시 파일은 접근권한을 제한한다.
6. 소스 해시·migration 수·실행 영수증·검증 범위와 미실시 범위를 별도로 남긴다.

## 착수 근거

root는 웹/관리자의 기존 password Credentials와 bcrypt 검증·JWT session 경로를 확인했다.
실제 Chrome의 loopback 합성 probe에서 HttpOnly `__Secure-`·`__Host-` Secure cookie 모두
다음 요청에 전달됨을 확인했다(chunk `70da4b`). 이것은 관리자 제품 로그인 통과가 아닌
브라우저의 로컬 cookie 동작만 확인한 증거다. probe 브라우저는 종료했다.

환경 수명주기는 codebase-design 지침에 따라 하나의 실행 도구가 소유하도록 설계하고,
Postgres 지침으로 격리·역할·transaction을 감사한다. 브라우저는 agent-browser의 전용 세션과
종료 규칙을 적용한다. Vercel 지침은 배포 대상/인증을 읽기 전용으로 확인하는 데 사용했다.

공식 문서: [NextAuth Credentials](https://next-auth.js.org/providers/credentials),
[Next CLI](https://nextjs.org/docs/app/api-reference/cli/next),
[PostgreSQL pg_ctl](https://www.postgresql.org/docs/current/app-pg-ctl.html).

최종 실행 결과는 아래에 단계별로 기록한다.

### DB 연결 사전 감사

설치된 postgres-js 3.4.9를 읽고 실제 생성 옵션 3개를 검증했다(chunk `c56b96`).
URL query의 `host`는 Unix socket host 선택이 아니며, URL의 `localhost`는 `PGHOST`보다
우선한다. URL-only 제품 DB client를 바꾸지 않고 hostname 없는 `postgres:///postgres`와
도구가 생성한 `PGHOST`·`PGUSER`·`PGPORT`를 함께 사용하는 경로를 선택한다.

root의 독립 `/tmp/cunote-root-uat-driver-audit.mjs`는 새 cluster에서 실제 연결의
`inet_server_addr() IS NULL`, `listen_addresses=''`, DB/user, exact socket path를 확인했다
(chunk `8ead52`). cluster는 정상 종료됐고 빈 테스트 데이터만
`/tmp/cunote-root-uat-driver-Z4aFXa`에 남았다. 제품 테이블·운영 DB 쓰기는 없었다.
이것은 DB 연결 전제 확인이며 실제 제품 로그인/저장 인수 통과는 아니다.

### 첫 runtime slice 감사

sol/xhigh가 `tools/product-uat/runtime.mjs`와 회귀를 추가했고 기본 16개 검사는 통과했다.
root의 독립 `/tmp/cunote-root-uat-runtime-audit.mjs`는 상속 비밀/실행 옵션 7개 제거를 확인했으나,
외부 source symlink·runRoot symlink·source 내부 destination을 거부하지 않는 3개를 재현했다
(chunk `79e7e5`). 실제 사용자/외부 파일이 아니라 root 소유 합성 임시 디렉터리에서만 시험했다.
따라서 이 시점에는 실제 제품 서버를 시작하지 않았으며 경로 소유권과 source 복사 제한을 보완 중이다.

후속 수정에서 caller 지정 runRoot를 없애고 새 mkdtemp 경로만 사용하며, Git 소스 inventory와
명시 allowlist로 복사를 제한했다. leaf뿐 아니라 모든 상위 symlink를 거부하고 `.envsecret`/
`.envrc`까지 제외했다. root의 현행 interface 독립 검사 **12개(상속 7+경로 5)**가 통과했다
(chunk `f55136`). 앞선 실패는 수정 이전의 기록으로 남긴다.

실제 source snapshot `cunote-product-uat-source-UYIO9Z`를 root가 독립 대조했다(`ed4f1a`).
2,200개 파일의 manifest SHA는 `09c12c42221839e98d5f2b7755c6d275101aca847572d15b030af64a2e0fde94`,
금지 경로 0, root/marker 권한 0700/0600이며 web/admin의 core/contracts 4개 참조 모두
snapshot 내부였다. 이 snapshot은 당시 runtime slice 증거이며 후속 fixture/runner의 최종 소스는 아니다.

root의 실제 runtime PG 검사에서 macOS locale 미설정으로 초기 기동 실패를 발견했다
(`a56f25`, `edca56`). DB 실행 env에 `LANG=C`, `LC_ALL=C`를 고정한 후
`/tmp/cunote-root-uat-lifecycle-audit.mjs`의 **14개 검사**가 통과했다(`f63c9c`).
정상 callback과 의도한 callback 실패 모두 URL client의 Unix 연결을 확인하고 cluster가 종료됐다.
테스트 데이터는 각각 `cunote-product-uat-pg-YxbpQN`, `cunote-product-uat-pg-R92E2H`에 보존했다.

### 실제 빌드·첫 로그인

새 빈 cluster에 기존 migration 83개를 적용하고 사용자 3명·회사 2개·소속 4개·관리자 1명을
seed했다. packages/web/admin production build와 loopback `next start` 두 개를 실행했다.
첫 실제 웹 로그인은 CSRF 발급 → 기존 password callback → 실제 사용자 UUID가 든 JWT session까지
통과했다. 비밀번호·cookie·CSRF는 영수증에 기록하지 않았다. 서버 두 개와 DB는 종료했다.

- 영수증: 임시 디렉터리 `cunote-product-uat-pg-e3v2cK/receipt.json`.
- 소스: `cunote-product-uat-source-GWGYkV/source-manifest.json`, 2,203개 파일,
  SHA `babd65320fd65a4be2274a43934070dbf4af6947d4068f5a1196b9f82d18511c`.
- root는 봉인 manifest를 독립 대조했다(`0fb427`). 금지 소스 경로·symlink가 없고,
  workspace 참조 4개가 복사본 내부였다. 빌드가 바꾼 복사본의 web/admin `next-env.d.ts`
  2개만 생성물 변경으로 구분했다. 원본 제품 소스 107개는 기존 검증 해시와 일치했다(`8efd63`).
- root의 소스 경계·비밀 환경 독립 검사 12개도 재통과했다(`17b5e5`).

이 단계에서 질문/공고 fixture는 넣지 않았다. 회사별 답변 저장·오소속 쓰기 거부·409·질문 개정/철회
인수는 위 로그인 증거로 대체하지 않는다. DB client는 `postgres` privileged role이므로
이 실행을 RLS 권한 검증으로 세지 않는다.

### 재현

저장소 루트에서 `node tools/run-local-product-uat.mjs`로 새 환경을 만들고 자동 검사 후 종료한다.
브라우저 독립 검사가 필요하면 `--hold-seconds=180`을 추가한다. 후속
[확인질문 화면 인수](2026-09-08-확인질문-화면인수.md)에서 명시 hold 상한을 600초로 확장했고
기본값 0(hold 없음)은 유지했다. 아래 기존 180초 실행 증거는 변경하지 않는다. 출력된 loopback URL과
접근권한 0600의 `connection.json`을 해당 제한 시간에만 사용한다. 이 파일에는 로컬 합성
비밀번호가 있으므로 출력·공유·커밋하지 않는다. 외부 OAuth/스토리지 자격증명은 넣지 않는다.
현재 도구는 이 macOS 환경과 설치된 PostgreSQL/pnpm 및 offline dependency cache를 전제로 한다.
임시 source·DB·로그·영수증은 재현 감사를 위해 보존하고, 실행 프로세스만 종료한다.

### 역할별 실제 HTTP·브라우저 최종 감사

무-hold 실행 `cunote-product-uat-pg-woRPti/receipt.json`(`09f510`)은 웹 3역할과 관리자 실제
로그인, owner A/B·editor A·viewer A 회사 목록, 오류 password/비로그인 401, logout 후 무세션,
relogin의 동일 UUID를 통과했다. 소스 SHA는
`b9acef9aa01230fbb8ad289e18ab3cdd7574e9ce950bb0507f40a91445169ab8`이며 root 대조도 통과했다(`de2b0f`).

별도 180초 hold 실행의 전용 브라우저에서 root가 실제 이메일/비밀번호 폼과 로그인 버튼을
사용했다. API 응답 대체나 cookie 위조는 없었다. 다음 9개 관측을 통과했다(`c754f2`).

- 웹 owner/editor/viewer 및 관리자 4개 실제 UI 로그인과 DB UUID/역할 일치.
- 브라우저 세션으로 실제 company API를 조회해 owner A/B·editor A·viewer A 확인 3개.
- 같은 브라우저의 웹 cookie만으로 관리자 인증되지 않음, 관리자 로그인 후 별도 웹 owner 세션 유지 2개.

영수증과 화면은 임시 `cunote-product-uat-pg-gzrA5U/root-browser-audit.json`,
`root-owner-companies.png`에 있다. root는 설정 화면의 합성 owner 이메일·회사 A 표시를 실제로
확인했다. 세 전용 브라우저 세션을 종료했고 기존 타 작업 세션은 보존했다(`2c258a`).
