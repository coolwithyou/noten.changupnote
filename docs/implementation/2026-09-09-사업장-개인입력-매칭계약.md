# 사업장 개인 입력과 매칭 계약

2026-09-09. R12의 `premises-v1` 최소 구현 계약이다.
구현·실제 인수·배포의 진행 상태는 [잔여 개선 실행 원장](../plans/2026-09-09-잔여개선-실행원장.md)을
따른다. 이 문서는 새 모델 실행이나 기존 분석 결과의 승격을 승인하는 문서가 아니다.

## 지원하는 의미

현재 등록 사업장의 **시도, 시설 유형, 절대 기준일**만 비교한다.
시설 유형은 본사·공장·연구소이며, 기존 시도 코드 목록을 사용한다. 시군구 catalogue를
새로 도입한 것이 아니다. 일반 소재지 `region`을 본사·공장 위치로 추정하지 않는다.

공고 조건은 `premises / required / exists`, `needs_review=false`여야 한다.
`value`는 `schemaVersion=premises-v1`, `state=registered_current_site`, 시도 코드 목록,
시설 유형 목록, `facilitySemantics=any`, 절대 `basisDate`를 갖는다.

원문 근거에 해당 날짜와 등록 관계, 같은 시설·시도 집합이 직접 있어야 한다.
note는 위험한 의미를 발견해 거부하는 데만 사용하며 원문에 없는 근거를 보충하지 않는다.
이 검사는 자유문장 전체를 이해하는 범용 규칙 언어가 아니라 보수적인 허용 범위 검사다.

다음은 범위 밖이며 자동 통과·탈락으로 바꾸지 않는다.

- 상대적인 공고일에서 날짜 추정, 시군구·특정 건물·입주 공간 조건.
- 이전 예정·미래 확약, 일정 기간 소재, 특정 증빙서류 보유 조건.
- 시설 AND, 지역과 시설의 짝을 각각 요구하는 OR, 부정·예외·열린 대안.
- 수출 실적·통화 환산·수출을 일반 매출로 대체하는 비교.

## 저장과 편집

사업장 목록은 최대 10개이며 각 행은 UUID, 시설 유형, 시도, 유효 시작일과 선택 종료일을 가진다.
확인 범위는 시설 유형 집합, 시작/종료일, `partial|complete`, 서버 관측 시각 `asOf`로 구성한다.
목록을 다시 열 때 기존 ID·행·종료일·확인 범위를 보존하고 명시적인 추가/삭제로 변경한다.
백그라운드 재조회가 편집 중인 draft를 초기화하지 않으며, 회사 전환은 편집 문맥을 분리한다.

이 값은 회사 공유 원천이 아니라 **사용자별 직접 답변**이다.
`self_declared / cunote_profile_question / user / portable_user_answer`와 실제 개인 저장 행의
scope가 모두 맞아야 사용한다. JSON에 user scope를 적는 것만으로 공유 행을 개인 정보로
승격할 수 없다. 익명 티저 입력과 system 재계산에는 개인 사업장 정보를 사용하지 않는다.

클라이언트는 `coverage.asOf`를 만들어 보내지 않는다. 서버가 사업장 답변 저장 때만 현재 시각을
부여하며, 저장된 정보 조회와 다른 필드 수정은 기존 관측 시각을 새로 쓰지 않는다.
손상된 JSON·잘못된 근거는 값을 복구하거나 추정하지 않고 사용할 수 없는 정보로 취급한다.
화면 편집 권한도 인증된 회사 역할에 결속하며 권한 정보 누락은 허용으로 취급하지 않는다.

## 판정 규칙

같은 사업장 행이 시설·시도·기준일을 모두 충족해야 한다. 서로 다른 행의 사실을 합쳐
가상의 적합 사업장을 만들지 않는다. 평가시점 이후의 관측이나 기준일을 덮지 못하는 확인
범위는 사용할 수 없다.

| 확인 상태 | 결과 |
| --- | --- |
| 유효한 같은 행이 모든 조건을 충족 | `pass`; 해당 시설이 확인 범위 안이면 partial도 가능 |
| 일치 행이 없고 필요한 시설·기간 전체가 complete로 확인됨 | `fail` |
| 일부만 확인·필요한 시설/기간 누락·부적절한 근거 | `unknown` |
| 빈 목록 또는 기준일에 유효한 행이 하나도 없음 | complete여도 `unknown` |
| 원문 의미나 구조가 지원 범위를 벗어남 | `unknown / criterion_invalid` |

빈 목록을 알려진 부재로 해석하는 기능은 구현하지 않았다. 사업장 입력은 선택적인 정밀화이며
기본정보 4개 완성률이나 자동채움 19축 분모를 늘리지 않는다. 기존 일반 자유문자 사업장 질문은
이 계약의 입력 수단으로 사용하지 않는다.

## 분석 경로와 역사 자산

추출 프롬프트·독립 검수·검증기·정규화·shadow projection·matcher는 공용 사업장 계약을 소비한다.
새 조건을 구조화할 때 의미 계약 버전은 전진하지만 과거 불변 receipt의 내용을 다시 쓰지 않는다.
source span 검증과 기존 release admission은 그대로 필요하다.

실제 과거 premises/text-only 24개에 새 typed 값을 자동 부여하거나 DB를 backfill하지 않는다.
공고의 원천·입력·첨부가 달라졌다면 별도 현행 검수와 exact release가 필요하며, UI 배포만으로
기존 공고가 새 자동판정 대상이 되었다고 보고하지 않는다.
