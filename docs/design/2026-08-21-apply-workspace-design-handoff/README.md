## 제품 목적

사용자는 공고 신청 양식을 원본 문서 형태로 보면서, 각 입력 칸을 AI와 함께 작성하고 검토한 뒤 정확한 칸에 반영합니다. 화면은 동시에 세 가지 질문에 답해야 합니다.

1. 지금 어떤 문서와 어떤 필드를 편집하고 있는가?
2. 현재 값은 저장됐고, AI 제안은 어떤 근거로 만들어졌는가?
3. 제안이나 대화 결과가 어느 입력 칸에 적용되는가?

## 핵심 사용자 흐름

1. 공고에서 지원서 워크스페이스로 진입합니다.
2. 상단에서 공고명, 작성 진행률, 현재 문서를 확인합니다.
3. 문서 편집기에서 원본 양식과 현재 작업 위치를 확인합니다.
4. 데스크톱은 오른쪽 AI 레일, 모바일은 하단 `AI 도우미` 버튼으로 필드 도우미에 진입합니다.
5. `필드 목록`에서 항목을 검색·필터링하고 작업할 필드를 선택합니다.
6. `작성 도우미`에서 현재 값, 위치 결속 상태, 근거 설명을 확인합니다.
7. 필요한 사실을 추가한 뒤 즉시 `제안받기`를 실행하거나 `대화로 작성`으로 1:1 대화를 시작합니다.
8. 대화 중 제안이 생성되면 현재 문서 revision과 필드 결속을 다시 확인한 뒤 정확한 필드에 적용합니다.
9. 문서 편집 결과를 서버에 저장하거나 편집본으로 내려받습니다.

## 화면별 기능 가이드

### 1. 워크스페이스 헤더

| 요소 | 기능 | 디자인 제약 |
|---|---|---|
| 공고 요약 | 이전 공고 화면으로 이동 | 현재 작업을 벗어나는 행동임을 명확히 표시 |
| 공고명 | 현재 작성 대상 식별 | 긴 제목은 한 줄 말줄임하되 전체 대상이 바뀌지 않게 유지 |
| 진행률 | 확인 완료 필드 수/전체 필드 수 | 숫자와 진행 막대를 함께 제공 |
| 문서 선택 | 신청서·사업계획서 등 작성 문서 전환 | 로딩·비활성 상태를 구분하고 선택 중인 문서를 항상 노출 |
| 안전 안내 | 빠른 작성에 포함되지 않는 구조를 설명 | 경고이되 오류처럼 보이지 않아야 함 |

### 2. 문서 편집 영역

- HWP/HWPX 원본 양식을 직접 편집하는 주 작업 표면입니다.
- 현재 과제 필드, 열린 쪽 수, 저장 상태, `지금 저장`, `편집본 다운로드`를 노출합니다.
- 저장 상태는 최소한 `불러오는 중 / 준비됨 / 수정됨 / 저장 중 / 저장됨 / 실패`를 식별할 수 있어야 합니다.
- 저장되지 않은 수정과 마지막 서버 저장 시각을 혼동하지 않게 표현해야 합니다.
- 반응형 화면에서도 동일 편집기를 두 번 마운트하면 안 됩니다. 문서 파서와 WASM 메모리 사용이 두 배가 되므로 하나의 편집기 노드를 레이아웃만 바꿔 사용합니다.

### 3. AI 필드 도우미

두 탭은 사용자의 의도를 분리합니다.

- `작성 도우미`: 선택한 한 필드의 현재 값, 결속 상태, 근거 입력, AI 제안, 적용 행동을 보여줍니다.
- `필드 목록`: 전체 필드 탐색, 검색, 상태 필터, 선택을 담당합니다. 필드를 선택하면 작성 도우미로 돌아옵니다.

필드 목록에 필요한 상태:

- 선택됨
- 위치 확인됨
- 위치를 확정하지 못함
- 미완료
- 검토 필요
- 현재 제안 생성 중
- 값 반영 완료

작성 도우미에 필요한 상태:

- 현재 확인값 또는 AI 제안 없음
- 제안 생성 가능
- 제안 생성 중
- 안전한 제안을 만들지 못함
- 요청 실패 및 재시도
- 검토할 제안 있음
- 제안 적용됨
- 적용 되돌림
- 제안 제외됨

주요 행동:

- `제안받기`: 회사 정보, 공고 근거, 사용자가 추가한 사실로 현재 필드의 제안을 생성합니다.
- `대화로 작성`: 현재 필드 문맥을 가진 1:1 대화 모달을 엽니다.
- `이 값으로 채우기`: 제안을 정확히 결속된 필드에 적용합니다.
- `최근 입력 되돌리기`: 직전 제안 적용을 복원합니다.
- `이 대안 제외`: 사용하지 않을 제안을 검토 대상에서 제거합니다.
- `다음 미완료`: 다음 작성 대상 필드로 이동합니다.

### 4. 1:1 대화 모달

대화는 사이드바가 아니라 큰 모달입니다. 데스크톱에서는 최대 `1280px` 너비로 화면 상하 24px, 좌우 최소 24px 여백을 사용합니다. 모바일에서는 화면 사방 16px 여백을 남기고 가능한 면적을 대화에 사용합니다.

모달 구성:

1. 제목과 현재 작성 필드 배지
2. 공고 기준 인사와 인용 근거
3. 사용자·AI 대화 내역
4. 최신 대화 이동 버튼
5. 필드에 반영할 사실 또는 수정 방향 입력창
6. 보내기 또는 생성 중단 버튼
7. 기관 전화·메일·공고 원문 연결

대화 상태:

- 대기
- 질문 전송 중
- 답변 스트리밍 중
- 사용자가 생성 중단
- 네트워크 실패
- 제한 시간 초과
- 같은 질문 재시도
- 추가 사실 필요
- 필드 적용 제안 준비

닫았다가 다시 열어도 현재 대화 컨트롤러와 필드 문맥이 유지되어야 합니다. 모달을 다시 여는 동작이 별도 세션이나 중복 질문을 만들지 않도록 설계해야 합니다.

### 5. 대화 콘텐츠 표시

- AI 답변은 과거 대화와 스트리밍 중 메시지 모두 같은 Markdown 렌더러를 사용합니다.
- 제목, 문단, 강조, 순서/비순서 목록, 인용문, 링크, 코드, 표, 구분선을 지원합니다.
- raw HTML은 실행하지 않고 원격 이미지는 직접 표시하지 않습니다.
- 긴 링크와 표는 대화 폭을 깨지 않도록 줄바꿈 또는 내부 가로 스크롤을 사용합니다.
- 공고 인용 배지는 한 줄 말줄임을 사용하고, 툴팁은 최대 240px·4줄로 제한합니다. 툴팁이 화면 폭이나 모달 레이아웃을 밀어내면 안 됩니다.
- 일반 지식 안내와 공고 근거가 있는 답변은 시각적으로 구분합니다.
- 스트림 chunk는 짧게 묶어 렌더링하며, 매 chunk마다 대화 전체가 흔들리거나 스크롤 위치가 튀면 안 됩니다.
- 사용자가 위로 스크롤해 과거 대화를 보는 동안 자동으로 하단으로 끌어내리지 않습니다. 새 답변을 따라가던 상태에서만 자동 스크롤하고, 그 외에는 `최신 대화로 이동`을 제공합니다.

## 반응형 동작

| 폭 | 현재 동작 | 재설계 시 유지할 기능 |
|---|---|---|
| `xl` 이상 | 편집기 + 360px AI 레일 | 문서와 현재 필드 정보를 동시에 비교 가능해야 함 |
| `xl` 미만 | 편집기 + 하단 고정 현재 필드/AI 도우미 버튼 | 주 작업을 가리지 않고 도우미 진입점을 항상 찾을 수 있어야 함 |
| 모바일 | AI 도우미를 오른쪽 시트로 표시 | 작성 도우미/필드 목록 전환, 내부 독립 스크롤, 닫기와 초점 복귀 |
| 모든 폭 | 대화는 중앙 모달 | 화면 크기에 맞춘 최대 면적, 안전 여백, 내부 대화 스크롤 |

모바일 캡처에서 문서 편집기 도구 모음과 문서 본문이 뷰포트보다 넓게 보입니다. 재설계 시 편집 기능을 손상하지 않으면서 현재 도구 모음, 문서 확대/축소, 가로 이동의 소유권을 명확히 해야 합니다.

## 반드시 보존할 안전 계약

1. **정확한 필드 적용**: 대화나 제안 결과는 현재 문서 revision에 결속된 exact 필드에만 적용합니다.
2. **추정 금지**: 필드 위치가 없거나 모호하거나 오래된 revision이면 임의로 적용하지 않고 실패 상태를 보여줍니다.
3. **적용 전 재검증**: 대화가 만든 `runId`, `suggestionId`, `fieldId`, 제안 값을 현재 revision에서 다시 확인합니다.
4. **저장 경계**: AI 제안 생성과 문서 저장은 별도 행동입니다. 제안이 보인다고 서버에 저장된 것으로 표현하지 않습니다.
5. **단일 채팅 세션**: 화면 표현이 바뀌어도 워크스페이스당 채팅 컨트롤러는 하나만 유지합니다.
6. **단일 문서 편집기**: 데스크톱/모바일용 편집기를 동시에 마운트하지 않습니다.
7. **안전한 Markdown**: 모델의 HTML과 원격 이미지는 실행·표시하지 않습니다.
8. **취소와 재시도**: 중단·시간 초과·재시도는 이전 서버 세션과 섞이지 않도록 새 세션 경계를 사용합니다.
9. **접근성**: 모달과 시트는 제목·설명·초점 가두기·Escape/닫기·원래 트리거로의 초점 복귀를 유지합니다.

## 재설계 우선순위

1. 문서, 현재 필드, AI 행동 사이의 시각적 위계를 단순화합니다.
2. 테두리와 중첩 카드 수를 줄이고 작업 흐름별로 정보 밀도를 조절합니다.
3. 대화 스트리밍, 실패, 취소, 재시도, 제안 적용 상태를 별도 컴포넌트 상태로 설계합니다.
4. 모바일 편집기와 고정 AI 진입점이 서로 가리는 문제를 해결합니다.
5. 필드 목록의 상태 아이콘과 필터 의미를 일관된 디자인 언어로 정리합니다.
6. 툴팁, 인용 배지, 긴 Markdown 표가 모달과 뷰포트를 벗어나지 않게 합니다.

## 증거 범위와 한계

- 스크린샷은 현재 개발 소스와 실제 브라우저 레이아웃을 증명합니다.
- 샘플 SSE는 Markdown 렌더링과 대화 레이아웃만 검증하며, 실제 모델 품질·인용 정확도·서버 세션 복구를 증명하지 않습니다.
- 모바일 캡처는 `390 × 844` 한 기기 크기만 다룹니다. 키보드가 열린 상태, 태블릿, 작은 모바일, 브라우저 확대는 별도 검증이 필요합니다.
- 이 문서는 디자인 재설계 입력물이며 프로덕션 배포나 사용자 수용 테스트의 증거가 아닙니다.
