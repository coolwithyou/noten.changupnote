## 구현

- 회사 사실 철회는 `company_fact_withdrawals`에 회사·의미 SHA별로 저장한다. 공고/질문에 FK를 걸지 않아 질문 무효화·원문 변경·공고 삭제 뒤에도 철회가 남는다. 회사 삭제는 cascade, 사용자 삭제는 작성자 null이다.
- 기존 권한·회사 잠금·원문 결속·답변 revision 검사를 통과한 같은 transaction에서 철회 행을 쓴다. RLS는 회사 구성원의 읽기만 허용하며 일반 역할의 직접 쓰기는 허용하지 않는다. 회사 입력 revision trigger로 매칭 캐시도 무효화한다.
- API와 matcher가 같은 철회 장벽을 읽는다. 재답변 시각은 같은 의미의 기존 답변/철회보다 뒤로 저장한다. 화면에는 값이 미해소여도 직접 저장된 answer revision을 반환한다.
- Popbill 공통 lease 획득 후 캐시·24시간 쿨다운·진행 중 guard를 재확인한다. 재확인에 실패하면 예산 예약·유료 호출 없이 자기 lease를 해제한다. 유료 결과가 불명확한 경우의 기존 영속 lease는 유지한다.
- UAT 환경의 migration 기준을 0092까지 올리고 런타임 import에 필요한 `samples/kstartup_announcement_sample.json` 한 파일만 snapshot에 허용했다. 다른 samples 파일과 환경파일·외부 symlink는 계속 차단한다.

## 실제 회사 계정 인수 중 발견한 문제 (2026-09-24)

사용자가 지정한 이메일로 실제 가입·로그인을 마쳤고, 제공한 사업자등록증을 근거로 회사와 업종을 등록했다. 비밀번호는 로컬 Keychain에만 저장했으며 문서·저장소에 기록하지 않는다. 증명서에 없는 매출·고용·인증 상태는 입력하지 않았다.

- 신규 회사의 현재 업력보다 오래된 APICK 관측이 우선 적용됐고, 공식 정보라는 이유로 사용자 정정도 거절됐다. 원인은 source policy의 30일 TTL을 해석기가 적용하지 않은 것이다. `expiresAt=null` 캐시와 저장된 관측 모두 TTL을 검사하도록 수정했다.
- Popbill 개업일 파생값을 일반 사용자 전용 파생 원천으로 잘못 분류했고, 저장된 공개 조회 관측도 동의가 필요한 재조회로 해석했다. 명시된 Popbill 원천 이름과 저장 scope를 보존해 공개 캐시와 사용자 동의 재조회를 구분한다.
- 만료된 공식 관측은 직접 입력을 막지 않도록 수정했다. 만료 이력과 관련 없는 저장 필드는 보존하며, 새 답변은 자가신고로 기록한다. 유효한 공식 관측의 정정 경계와 사용자 전용 재조회 동의는 유지한다.
- 공개 사업자 정보 재조회는 실제 1회만 실행했다. 개업일은 현재 업력을 뒷받침하지만 외부 상호는 증명서의 변경 상호와 달랐다. 외부 결과를 임의 변경하거나 연속 재조회하지 않았다.

**모집단 해석 정정:** 위 가상 회사 평가의 105건은 `requireDeepAnalysisPromotion`을 적용한 제한된 조회다. 실제 인증 제품 경로는 discovery를 포함한 1,514건을 평가했다. 105건을 현재 제품 전체 후보 수로 해석하지 않는다. 실제 계정에서 처음 확인한 즉시 추천 가능 수는 0이었으며, 후보 카드의 표시만으로 추천 품질 인수를 통과했다고 판단하지 않는다.
