## 재개 절차

구조적 오류의 원인과 교정 정책을 문서·코드에 반영하기 전에는 아래 명령을 실행하지 않는다.

1. 사용자가 발견한 구조적 오류를 재현하고 현재 artifact와 대조한다.
2. 교정 코드와 회귀 테스트를 추가하고 딥분석 계약·에이전트 테스트·타입 검사를 통과시킨다.
3. 새 성공 런이지만 새 검수 artifact가 없는 `b95a…`, `7224…` 두 건만 Fable → Sonnet → Opus 순으로 검수한다.
4. `7224…`의 Kordoc 미해결 후보 1건을 별도로 확인한다.
5. 고정 30건 최신 성공 런의 품질 그래프를 다시 계산한다.
6. 그 결과가 여전히 교정을 요구할 때만 위 여섯 공고를 정확한 ID로 제한해 재개한다.

재개 시 공통 환경 경계는 다음과 같다.

```bash
ANALYSIS_LAB_TIMEOUT_MS=1800000 \
ANALYSIS_LAB_TRANSPORT=claude-cli \
ANALYSIS_LAB_MODEL=claude-opus-5 \
ANALYSIS_LAB_ROUNDTRIP_MODEL=claude-opus-5 \
ANTHROPIC_API_KEY=
```

전체 자동 선정이나 `lab:agent --execute`부터 다시 시작하지 않는다. 먼저 위 2건의 검수와 30건 그래프 재계산으로 정확한 재개 집합을 만든다.
