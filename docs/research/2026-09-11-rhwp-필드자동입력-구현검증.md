# RHWP 누락 필드 보완과 회사 정보 자동 입력 구현 검증

2026-09-11 KST. 이 세션이 통합 관리하고 구현은 `gpt-5.6-sol / xhigh` 에이전트 3개가 담당했다.
대상은 사용자가 지정한 `87d36b6f-23f3-4484-8f08-fe8394ba5e10` 한 공고다.
**상태: 코드 구현과 로컬 검증 통과. 새 v11 live 분석, 운영 배포, 서비스 필드 승격, 실제 자동입력 브라우저 인수는 미완료다.**

## 원인과 범위

정식 대량분석에는 필드 분석이 있지만, 이 공고의 과거 작성 가이드 분석은 이를 제외했다.
또한 로컬 분석 결과와 서비스 DB 필드 반영은 별도 단계다. 기존 applied release에는
`not_applicable / fields=0 / roundtripRunId=null`인 precompute receipt가 있었으므로
성공한 필드 분석으로 볼 수 없었다. 코드 수정만으로 현재 서비스의 필드 0개 상태는 해소되지 않는다.

전체 필드 0건 재고 312개에 대한 일괄 실행은 하지 않았다. 다른 세션의 편집기 검증과
계획 산출물을 참조했고, 이 세션에서 분석·native 위치·회사 자동입력을 분담했다.
다른 외부 세션에 명령을 전달하거나 중복 구현을 시작시키지 않았다.

## 구현

- 필드 없는 공고는 기본 분석 이력만으로 `skip_existing` 처리하지 않도록 exact 보완 준비 경로를 추가했다.
- 완결된 신청서 분석을 재사용할 때 증빙용 동의서의 의도적인 field planning 생략을 허용한다.
  신청서 역할, 모든 문서의 원본·해시, 성공 상태 검증은 유지한다.
- rowSpan 그룹의 첫 하위 라벨인 `담당자`를 복원했다. 실제 오른쪽 빈 값 셀이 있어야 하며,
  `총 인원 : 명` 같은 값 placeholder는 계속 제외한다. 담당자와 대표자를 동일시하지 않는다.
- 같은 셀 안 숫자 2영역과 신청분야 체크박스 3영역은 안전한 세부 쓰기 위치를 지원하지 못한다.
  새 쓰기 후보나 값을 추정하지 않고 5개 structural warning으로 남겨 `partial / conditional / CONTINUE`로 기록한다.
- 분석 계약을 v11로 전진시켰다. 기존 v10 receipt는 보존하고 새 계약의 ready 결과로 재사용하지 않는다.
- RHWP 진입 시 저장된 회사 profile seed와 유일한 빈 표 셀을 exact fieldId로 연결해 입력한다.
  수기·AI·승인·기각 답변, 안내문, 이미 채운 셀, 중복 라벨은 자동 입력에서 제외한다.
- 미승인 template 답변은 유일한 canonical 회사 필드일 때만 profile 답변에 재결속한다.
- 자동입력 문서 revision과 답변 상태를 같은 DB transaction에서 갱신한다.
  Undo는 같은 세션의 변경되지 않은 revision에서만 허용하고 기각 상태를 저장해 재주입을 막는다.
- 문서 전환 시 지연 응답이 다른 문서를 바꾸지 않도록 source/session/request를 확인한다.
- 자유서술의 잘못된 아래 셀 탐색을 차단했다. 실제 양식의 cell39 안내문과 cell40 선언·서명을 구분한다.
  source에서 증명한 same-cell metadata, exact 첫 문단, 균일한 글자 서식이 모두 확인될 때만
  고정 안내문 뒤에 본문을 추가한다. 일반 오른쪽/아래 장문 입력 셀은 별도 경로로 유지한다.

## v10 분석·독립 검수 이력

첫 단건 manifest `54efcac2aa15f3e443725e48d1c11547231faa8be27b80c421af2c874b47c919`,
receipt `564bbcf331d23b59ca4fb982da9a29b84fcca7c2f5ec17a1473663e5a5538c0d`에서
신청서 1개·증빙 1개를 분석했고 입력 필드 15개를 추출했다. 실행은 로컬 claude CLI
Max 인증을 확인한 구독 경로였다. 운영 worker 설정은 변경하지 않았다.

첫 독립 검수는 노동자 수 중복 조건, 두 번째는 기업 규모 과확정을 지적했다.
성공한 신청서 분석은 재사용하고 primary만 보정했다. 세 번째 receipt
`e72cd603049fcccc85c8ef939e3536f0f71aded3509e26d63762d7dad1cea9af`에 대한 aggregate
`e328d7df6d9421efeb88027d65190de74cfa5d77b7c535659a9276d367e27749`는 PASS,
defect 0 / unresolved 0이다. 검수 첫 실행 timeout 후 같은 packet 재시도가 통과했다.

이 PASS는 기존 v10 15개 필드에 대한 이력이다. 이후 담당자 누락, 미지원 세부 입력,
보호할 고정 문단 계약을 반영한 v11을 새로 분석했다. 원래 immutable 결과와 검수는 수정하지 않았다.

## 승인 후 v11 실행과 필드 전용 반영 준비

사용자는 같은 공고 한 건의 v11 실행·독립 검수, 정확한 소스 push·웹 배포, 공식 서비스 반영과
브라우저 검증을 승인했다. 첫 실행은 이전 v10 이력을 새 분석으로 오인해 모델 호출 0회로
건너뛰었다. 실제 batch scanner에 분석 버전 검증을 추가하고 같은 대상·원본·모델 범위로 재실행했다.

새 launch receipt는 `113d00049bb9a583b8be47f6face9e8426231059f97439f76fbfa0261eb0a57d`,
roundtrip은 `roundtrip-2026-09-11T020705.283Z-51f792`다. 신청서의 입력 필드 16개를 확보했고
미해결 후보는 0개다. 안전하게 입력 위치를 정할 수 없는 다중 슬롯·체크 영역 5개는
구조 경고로 보존해 `partial/conditional/CONTINUE`로 종결했다. 독립 검수 aggregate
`70ca14765531ecf8f75978fdb498d9451177cbac59cf3a5a6e680bf64b80a201`는 PASS, defect 0이다.

서비스의 기존 active release는 9건이고, 대상의 primary snapshot은 기존 적용 receipt와 같다.
서비스 필드는 여전히 0개여서 ordinary 재승격의 중복 거부를 우회하지 않고, 기존 item을
exact parent로 결속하는 `application_field_repair` 전용 release 경로를 추가했다. 이 경로는
criteria·질문·매칭 상태·기존 release/item·사용자 draft를 바꾸지 않는다. 새 원장 테이블만 추가한다.
후보 artifact DB 행, 필드와 surface, 적용 receipt는 같은 transaction으로 기록한다.

작성 준비도는 원본·surface·field hash로 검증하고 사용자 draft 변경은 이 hash에서 제외한다.
사용자 작성본의 보존 여부는 반영 transaction의 별도 before/after digest로 검사한다.
서비스 repair 삭제 rollback은 동시 사용자 작성의 JSON 참조를 안전하게 보호할 공통 잠금이
없으므로 지원하지 않는다. 문서 편집기에서의 사용자 Undo와는 별개다.

## 적용 순서와 미완료 단계

운영 `NOTEN/changupnote`의 관측 SHA는 `838bace3c8ad8f34a5a4d661cbaa06af4a8a7484`이며
`CUNOTE_FIELD_EDITOR_AGENT_ENABLED=true`, repository adapter는 drizzle이다.
이 SHA의 binder는 자유서술을 아래 cell40 선언·서명에 결속할 수 있다. 운영 DATABASE_URL은
masked 상태라 로컬 값과 byte 비교하지 않았지만, 공식 promotion은 서비스 데이터 변경이다.
**새 필드의 DB 승격 전에 안전한 웹 수정본을 배포해야 한다.**

같은 공고 한 건의 v11 분석·독립 검수는 완료했다. 승인된 후속 범위는 필드 전용 반영 경로의
통합 검증, 추가 테이블 migration, 정확한 소스 commit/push·운영 웹 배포, 공식 repair release 적용,
실제 RHWP 브라우저 인수다. 이 문서의 소스 작성 시점에는 서비스 필드 쓰기와 새 웹 배포를
아직 실행하지 않았다. 최종 활성화 결과는 별도의 실행 증거로 기록한다.
