# 기업명 입력칸 누락 후속 점검 및 수정

기준 소스: `0a5438d973aef08b85e7c69b92862bfd2abbfbdc`. 점검 대상은 2026-09-16 승인 실행의 로컬 결과 35건이다. 지원기간이나 운영 서비스 상태를 새로 조사한 작업은 아니다.

## 결론

경북 푸드테크 사업계획서의 기업명 누락을 코드에서 수정했다. 원문에 독립된 기업명 값 칸이 있고 같은 행의 대표자도 label→빈칸 쌍이라는 구조 증거가 있을 때, 기업명을 앞 구획 라벨의 값으로 잘못 제외하지 않는다.

또한 “값 placeholder 가능성”만으로 빈 필드를 확정 제외하던 coverage 규칙을 제거했다. 이 변경은 의심 후보를 모두 입력칸으로 복원하는 것이 아니라, 근거가 부족한 제외를 `review_required`로 드러낸다. 기존 v19 분석은 그대로 보존했으며 새 버전으로 이름만 바꿔 승계하지 않는다.

## 원인과 수정 경계

원문 block20 row0은 `[기본정보, 기업명, 빈칸, 대표자, 빈칸]`이다. KorDoc이 `기본정보.originalValue=기업명`으로 읽으면 중복 제거가 실제 기업명 후보를 likelihood 0.15로 낮춘다. 그 결과 모델 판정 대상에서 빠지고, coverage도 “placeholder 가능성”을 확정 비입력 근거로 받아 누락을 숨겼다.

수정은 다음 조건을 모두 요구한다.

- 기존 `kordoc-form` 후보가 억제 전부터 추천 입력이며 empty이고 originalValue가 비어 있다.
- 앞 후보 originalValue와 현재 라벨의 정확한 일치가 중복 억제의 원인이다. 단순 suffix 일치에는 적용하지 않는다.
- IR의 실제 라벨 텍스트와 좌표가 일치하고, span 끝 바로 오른쪽에 독립 빈 값 셀이 있다.
- 라벨은 짧은 기본정보 항목의 exact 집합에 해당하고, 같은 행에서 다른 기본정보 라벨→빈칸 쌍도 확인된다.
- 앞 셀이 명시적으로 예시·예제·작성예를 나타내면 자동 보존하지 않는다.

단위, 예시 분류값, 머리글 연쇄, 빈칸 없음, 단일 책임자 쌍, suffix 중복은 자동 복원하지 않는다. 검증된 span-aware 제외는 기존처럼 유지한다. native writer나 confidence 임계는 변경하지 않았다.

## 남은 작업

확정된 기업명 누락은 로컬 수정·재현 검증까지 마쳤다. 다른 미확정 후보는 원문과 writer 좌표에 근거해 제외 또는 입력 여부를 구분해야 한다. 코드가 바뀌었다는 이유로 기존 35건의 모델 분석을 통째로 다시 실행하지 않는다. 성공 본문·원 결과는 보존하고 영향을 받는 신청서 단계의 exact 후속 범위를 준비한다.

이 작업에서 모델 호출0, DB/R2 쓰기0, release 승인·promotion0, 배포0이다. 한글 앱에서의 육안 확인과 로그인한 사용자의 브라우저 작성·다운로드 검증은 별도 미실행이다.
