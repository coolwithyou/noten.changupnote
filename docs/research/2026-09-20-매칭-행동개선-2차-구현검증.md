# 매칭 행동 개선 2차 구현 검증

작성일: 2026-09-20 KST. 사용자 “계속 진행해줘”에 따른 후속 코드 구현. 작업 트리 기준이며 커밋·배포·서비스 DB 변경은 하지 않았다.

## W5 계측 저장 경로

기존 `match_events`에 선택 JSON `journey`를 추가하는 0086 migration을 준비했다. 새 수집 서비스는 도입하지 않았다.

- 카드 열기, 회사 정보 입력 시작, 공고 질문 시작, 상세 이동, 신청 준비 시작을 구분한다.
- Programs 결과 마운트부터의 경과 시간과 메모리 내 임의 세션 키를 기록한다. 회사 전환 시 새 키를 만들며 다른 카드에서도 같은 결과 세션을 공유한다. 화면 실제 노출 시각·서버 검증 시간은 아니다.
- 입력값·사업자번호·공고 제목·원문·답변을 보내지 않는다. 서버가 version/session/action/elapsed/evidence/eligibility만 재구성한다. arbitrary payload는 저장하지 않는다.
- 웹 이벤트 요청에 명시적 companyId를 전달하고 기존 회사 쓰기 권한 검증을 사용한다. 잘못 지정한 회사가 쿠키 회사로 대체되지 않는다.
- 익명·가상 회사와 webdriver 이벤트는 클라이언트에서 제외한다. 로그인 회사 쓰기 권한이 있는 경로만 현재 범위이며 전체 사용자 표본이 아니다. 사람이 생성한 합성 회사나 webdriver를 숨긴 자동화까지 식별한다고 주장하지 않는다.
- transport 실패는 기본 행동을 막지 않는다. 메모리 저장소는 `persisted:false`, DB 저장소는 `persisted:true`를 영수증에 넣는다. 기존 accepted의 요청 수락 의미는 유지한다.
- 서버 `CUNOTE_MATCH_JOURNEY_ENABLED=true`일 때만 새 데이터를 쓴다. 이번에 활성화하지 않았다. 비활성 204는 저장 영수증이 아니다.
- 클릭 이벤트의 세부 유형이며 신청 완료 이벤트가 아니다. 기존 클릭 통계와 새 버전의 세부 행동을 섞어 전환율을 계산하지 않는다.

적용 순서: 검증된 소스 확정 → 기존 migration 절차로 0086 적용 → 배포 → flag 활성화 및 실제 로그인 회사 인수. ORM 스키마의 관리자 전체 열 조회도 추가 열을 포함하므로 배포 전에 migration이 필요하다. 일반 이벤트 INSERT는 기존 열을 명시하여 비활성 경로 호환을 유지했다.

남은 계측: 화면 노출 분모와 행동 없음, 질문 시작/완료의 동일 세션 연결, 원문·공식 신청 이동, 영속 이벤트 집계 보고서. 기존 profile_question_events의 서버 답변 영향 기록과 새 카드 세션은 아직 연결하지 않았다. 현재 데이터로 전체 질문 완료율·이탈률을 계산해서는 안 된다. 프로덕션 지표는 미수집이다.

## W6 오프라인 복합 조건 검증

`packages/core/src/matching/compound-projection.ts`는 운영 matcher를 바꾸지 않는 검수용 모듈이다. 원문 자동 해석·LLM 호출은 없으며 existing receipt를 수정하지 않는다.

- version `compound-projection-v1`, exact source revision SHA, 필수·제외 criterion 집합을 받는다.
- OR: 한 경로 pass이면 pass, 모두 fail이면 fail, 나머지 unknown.
- AND: 한 조건 fail이면 fail, 모두 pass이면 pass, 나머지 unknown.
- OR 결정 경로의 criterion ID를 보존하고 불필요한 다른 분기의 pending을 제거한다.
- 빈 그룹, 중복/누락/다른 criterion, 잘못된 구조, 깊이/노드 상한 초과와 source drift는 unknown/error다. 통과 경로가 있어도 다른 분기의 구조 오류를 숨기지 않는다.
- 18개 truth table와 중첩 fixture를 검증했다. “분야 AND (GBC OR 유럽 진출 희망)”은 합성 fixture이며 실제 공고 검수·승격 근거가 아니다.

남은 연결: 실제 current 원문 검수 artifact와 projection의 승인 결속, 운영 trace/질문/planner/quality 전체 소비자 정합성, 열린 목록·예외 표현, before/after shadow 리포트. 운영 연결 전까지 자격 판정은 기존 flat matcher를 유지한다. 이 기반 구현을 W6 전체 완료로 취급하지 않는다.
