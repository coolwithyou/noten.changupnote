## 기존 개선이 적용된 부분과 아직 확인되지 않은 부분

3건 모두 최초 primary 결과로 종료했으며 결정적 보정과 모델 보정 모두 0회다.
semantic fingerprint와 terminationReason=accepted가 실제 LabRun에 남고, 요청별 시작·종료·토큰 관측 10개가 누락 없이 기록됐다.
첫 공고의 신청서 보류가 다음 공고의 착수를 막지 않았고, 평가표를 신청서로 오인해 모델을 호출하지 않았다.
TECHFEST의 일반 7년·신산업 10년 복합 업력은 text_only로 보존되어 단순 83개월 기준으로 강제 변환되지 않았다.

이번 표본에서는 `semantic_no_progress`, failed-primary RHWP exact reuse, 단순 `7년 미만` 수치 보정이 발동하지 않았다.
이 분기들의 근거는 관련 오프라인 회귀 테스트이며 이번 실측의 성능 개선 원인으로 계산하지 않는다.
이전 표본 339.833초·primary 6회와 현재 249.660초·3회의 차이는 서로 다른 공고·문서량에서 나온 값이다.
현재 결과를 통제된 26.5% 성능 향상이나 대규모 p95 개선으로 주장하지 않는다.

## 확인한 결함과 이번 후속 수정

### 1. 신청서 필드명의 띄어쓰기 때문에 원문 문맥 누락

안성 공통 신청서의 `신 청 내 역`은 원문에서 `<td colspan="6">신청내역</td>`인 구획 제목이다.
아래 행에는 구분·발송비용·국내운송비·국제운송비·샘플배송비 입력란이 따로 있다.
해당 후보는 2회 재판정 뒤에도 불확실하여 미해결 1개로 안전하게 보류됐다.
최종 후보에는 원문에 없는 작성 안내 helperText가 생성되어 있어 단순 문자열 검색에 실패했다.
최초 요청 payload는 보존되지 않았으므로 모든 원래 요청의 문맥이 비었다고 단정하지 않는다.

후속 코드는 기존 exact 검색의 순서와 결과를 보존하고, 실패할 때만 **한글 음절 사이 수평 공백**을 정규화한다.
유일한 일치를 원문 UTF-16 offset으로 되돌려 HTML 구조가 포함된 원문 구간을 전달한다.
숫자·영문·기호·행·페이지·문단 경계는 합치지 않고 정규화 중복은 선택하지 않는다.
저장된 최종 후보 191개를 모델 없이 재검사한 결과 기존 문맥 유실 0, 원문 문맥 회복 4개였다.
회복 대상은 `설 립 일`, `신 청 내 역`, `합    계`, `작  성  자`이며 모두 원문의 정확한 연속 구간이다.

이는 문맥 회복의 오프라인 증거다. 실제 모델이 제목을 제외했거나 재판정 2회를 절감했다는 증거는 아직 없다.
두 재판정 요청은 합계 약 21.055초였지만 primary와 겹쳐, 없애더라도 이번 target wall 감소를 보장하지 않는다.
기존 exact 검색에서 반복 label의 첫 위치를 선택하는 문제는 IR 위치 결속이 필요한 후속 과제로 남겼다.

### 2. 포괄 업종 조항의 중복 구조화

TECHFEST criterion 12는 실제 제외업종 4개와 구체 업종이 특정되지 않은 법률 위임 조항을 tags에 함께 넣었다.
criterion 13에는 같은 위임 조항이 text_only로 이미 있었다.
기존 프롬프트가 “포괄 행을 tags에서 누락하지 마라”와 “별도 text_only로 보존하라”를 함께 지시한 모순을 확인했다.
수정한 지침은 식별 가능한 업종을 tags에, 위임 조항을 같은 kind의 text_only에 보존하도록 구분한다.
코드가 없다는 이유만으로 실제 업종명을 제거하지 않도록 했다.

### 3. 평가조건에 발표 참여 절차 혼입

TECHFEST criterion 21에는 영어 발표평가의 글로벌 준비·성장 가능성 외에 대표자 참석·직원 대리 참석 규칙이 섞였다.
preferred에는 점수·순위를 바꾸는 사실을 유지하고 참여 절차는 analysis_markdown/신청 주의사항으로 분리하도록 지침을 보완했다.
영어 역량 평가나 절차 자체에 명시적으로 부여된 배점은 삭제하지 않는다.
두 결함을 광범위한 정규식으로 자동 삭제하거나 기존 LabRun을 고치지 않았다.

### 4. 관측 정확성

실제로 모델 호출을 시작하지 않은 비신청 문서 skip 경로만 요청·토큰·명목 비용을 명시적 0으로 기록한다.
모델 호출 후 실패했을 수 있는 경로의 누락 값을 임의로 0으로 바꾸지 않는다.
CLI 진행 로그는 primary 성공과 신청서 ready/held/not_applicable을 나눠 출력한다.
신청서 관측 자체가 없는 이벤트는 not_observed로 표시하며 최종 target 판정은 receipt를 따른다.

후속 코드 계약은 RHWP v12, lab-deep-v24, deep prompt v29로 올렸다.
gpt-6-astra high가 원문·프롬프트 의미 경계와 최종 diff를 검토했고 blocker는 없었다.
공백 정규화가 수직 제어 문자까지 합칠 수 있다는 자문을 반영하여 수평 공백으로 제한하고 반례를 추가했다.

## 추가 시간 단축의 우선순위

1. **정확한 문맥과 모순 없는 지침으로 재판정을 예방한다.** 이번 수정은 모델·임계값·검수 기준을 유지한 상태에서 적용했다. 후속 실측에서는 필드 보류율과 독립 검수 지적이 함께 줄었는지 확인해야 한다.
2. **primary 응답 비용을 먼저 측정한다.** 최초 응답이 51–128초이므로 reasoning effort와 출력 중복을 하나씩 비교할 가치가 있다. 현재는 같은 모델·effort를 유지했으며 품질 검수 없이 축소하지 않았다.
3. **공고 동시성 2를 별도 exact 실험으로 비교한다.** 이번 시간들이 그대로 유지된다는 이상적 2-worker 스케줄은 약 129초지만, 실제 구독 경쟁·슬롯 배분·timeout·품질은 검증되지 않았다. 측정된 절감치나 실행 약속이 아니다.
4. **필드 위치에 결속된 문맥을 제공한다.** 반복 label·nested table에서 텍스트 검색의 한계를 줄이려면 원문 IR 위치 연결이 필요하다. 동명이인 label을 임의로 선택하는 전역 완화는 피한다.
5. **분석 시간을 품질 통과까지 측정한다.** 현재는 독립 검수 2개 지적과 신청서 보류가 남아 있어 전체 성공 결과를 얻는 총시간은 아직 산출할 수 없다. 빠른 primary 종료만으로 목표 달성을 선언하지 않는다.

새 실측은 새 exact manifest에 결속해야 한다. 기존 실험의 실패·보류 artifact는 그대로 보존했다.

`pnpm lab:launch:test`, `pnpm lab:roundtrip:test`가 모두 통과했다.

브라우저 UAT와 웹 배포 build는 UI 변경이 없어 추가 실행하지 않았다. 실제 모델의 수정 후 품질·속도는 미검증이다.
