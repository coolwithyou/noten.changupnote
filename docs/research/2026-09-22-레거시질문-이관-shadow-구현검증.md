# 레거시 질문 이관 shadow 구현 검증

## 목적

기존 질문을 새 3상태 평가 계약으로 일괄 변환하지 않고, 현재 지원기간 안의 동일 snapshot에서 기존 노출과 strict v2 노출을 비교한다. 질문별 criterion·source binding·구조·답변 존재 여부를 대조해 exact 이관 후보와 수리 대상을 분리한다.

구현은 서비스 DB를 repeatable-read/read-only로만 읽는다. 모델 호출, 질문 발행, migration, 답변 변경, 서비스 DB 쓰기는 수행하지 않는다.

## 판정 계약

| 판정 | 의미 |
| --- | --- |
| `verified_v2` | current source와 serving run에 결속된 검증된 v2 질문 |
| `legacy_review_candidate` | 원문 근거와 구조는 충분하지만 극성·공유 범위 사람 검수가 필요한 legacy 질문 |
| `legacy_answer_preservation_review` | 기존 답변이 있어 의미 mapping과 답변 보존 검수가 추가로 필요한 질문 |
| `legacy_structure_repair` | criterion 검수 또는 질문 해소 주체를 먼저 바로잡아야 하는 질문 |
| `v2_blocked` | v2이지만 current source/serving 결속을 증명하지 못한 질문 |
| `not_applicable` | application 전용·우대 조건이거나 회사 프로필로 직접 판정해야 해 공고별 질문으로 이관하지 않을 조건 |

모든 entry는 `automaticMigrationAllowed=false`다. legacy `disqualifies` 값을 v2 `satisfied|unsatisfied|unknown`으로 추정 변환하지 않는다.

## 다음 구현 경계

22개 검수 후보는 현재 원문과 criterion에 결속된 수동 검수 packet으로 만든다. 17개 구조 수리 대상은 질문 문구 수정이 아니라 criterion 해소 주체를 먼저 바로잡는다. 3개 profile-resolvable 질문은 새 질문을 만들지 않고 회사 정보 비교 경로가 실제 카드 판정을 갱신하는지 shadow로 검증한다.

이 단계에서는 production migration, 질문 재발행, 사용자 노출 변경을 수행하지 않았다.
