## 이번 변경

1. ladder B에서 회사 정보 자동 입력·항목별 AI 작성을 사용할 수 없는 이유를 표시한다.
   문단·셀 제안과 항목별 제안을 기능 상태 문구에서도 구분한다.
2. `lab:launch:prepare-field-repair`를 추가했다. 명시한 UUID만 받으며, 신규 모집단의
   과거 이력 제외 규칙은 유지한다. 보완 대상은 현재 지원 가능·공개 상태이고, 필드가
   0개이며 R2 보관본에 연결된 편집 가능한 HWP/HWPX surface가 있는 공고다.
3. 독립 `current-field-repair-*` inventory와 `missing-fields-v1` 정책을 봉인한다.
   입력·첨부·source revision을 준비 전후와 봉인 직전에 확인한다. 기존 승인형
   `lab:launch` 실행 경로를 사용하고, 모델 착수 직전에도 필드 0개 조건을 재검사한다.
   기존 필드가 생기면 보완을 중단하므로 다른 분석·검수 결과를 덮어쓰지 않는다.
4. launch의 `skip_existing`은 현행 primary publishable 여부만 보지 않는다.
   `withApplicationRoundtrip=true`인 실행은 현행 필드 분석 ready가 없으면 과거 primary가
   publishable이어도 pending으로 분류한다. 반대로 현행 v10 ready artifact가 이미 있고
   DB에만 미적용인 공고는 기존 receipt의 exact release 경로를 쓸 수 있어 불필요한
   모델 재실행을 하지 않는다.

```bash
pnpm lab:launch:prepare-field-repair -- \
  --grant-ids=87d36b6f-23f3-4484-8f08-fe8394ba5e10 --concurrency=1
```
