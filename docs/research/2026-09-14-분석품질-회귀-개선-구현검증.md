## RHWP 및 검수 실행기 구현

RHWP `kordoc-application-roundtrip-v13`은 실제 KorDoc IR의 후보 block/row/col에서 문맥을
만든다. 대상 셀을 먼저 기록해 긴 표에서도 잘리지 않게 하고, 인접 문맥은 길이를 제한한다.
구조 문맥을 요청한 경로에서 위치를 찾지 못하면 문서 앞부분의 동일 문자열로 대체하지 않는다.
좌표 메타데이터와 원문을 분리해 같은 원문을 요청에 두 번 넣지 않는다.

비입력 판정은 신뢰도와 해당 문맥의 인용을 함께 확인한다. 위치가 다른 인용·근거 누락은
uncertain으로 남기고, 이전 라운드의 비입력 설명·높은 신뢰도·고정 기호 설명이 이를 다시
검수 통과로 닫지 못하게 했다. 기존의 결정적 비입력 규칙은 보존한다.
이 검증은 위치가 다른 근거를 차단하며, 같은 문맥 안에서 모델이 의미를 잘못 해석하는 모든
경우까지 정답을 보증하지 않는다. 실제 값 쓰기 위치와 저장 결과의 UAT도 별도다.

독립 검수 CLI는 새 출력이 180초 동안 없으면 정체로 처리한다(`--stall-timeout-ms`로 조정).
기존 전체 제한은 유지하며 동일 packet의 재시도는 최대 한 번이다. 실행 중 stdout/stderr와
진행 이벤트를 attempt별 파일에 남기고, 완료 결과는 packet·sequence·model 결속을 확인해
재사용한다. 실행 전후 packet SHA를 재확인하며 입력이 바뀌면 완료 결과를 저장하지 않는다.

Unix에서는 이 실행이 만든 process group에 TERM→KILL을 보내 launcher의 자식까지 종료를
확인한 다음 재시도한다. 실행 중이거나 상태가 불분명한 lock은 빼앗지 않는다. 종료를 확인하지
못하면 lock을 보존한다. 이 구현의 process-group 검증은 macOS에서 수행했다.

fake Codex 통합 검증은 정체 후 성공, 두 번 연속 실패, 실행 전후 입력 변경, 실행 중 로그,
완료본 무호출 재사용, grandchild 종료를 포함한다. 실제 CLI main에 SIGTERM/SIGINT를 보내는
검증도 각각 통과했다. 추가 attempt가 없고 child/grandchild가 종료됐으며, 실패 진행 기록과
종료 후 lock 해제·재획득을 확인했다. `treeTerminated=false`/EPERM 강제 주입은 수행하지 않았다.

## 원문 한계와 준비도

공용 결과의 `sourceLimitations[]`는 자격 상세·신청 절차·기타 정보의 범위를 구분한다.
명시적 참조, 제한된 입력 범위에 대한 판단, 모델의 자체 미확인 고지를 구분하고,
근거는 실제 제공한 chunk의 ID·종류·SHA·연속된 원문 인용으로 검증한다.
null SHA라도 현재 chunk와 인용 검증은 생략하지 않는다. 확인하지 못했다고 추정한 파일을
실제 제공 출처로 만들거나, 영향을 모르는 상태를 전축 누락으로 바꾸지 않는다.

유효한 자격 관련 한계는 공용 validator의 `source_incomplete`로 처리한다.
실험실은 기존 확인 축 수 정책에 따라 conditional/deferred를 유지하고, 운영 경로는 기존
primary hold 처리로 연결된다. 절차 한계만으로 매칭 준비도를 낮추지 않는다.
현행 모델 tool schema는 빈 배열까지 반환하게 하고, 역사 artifact의 필드 부재는 허용한다.
최종 독립 코드 검토에서 현행 응답의 필드 누락도 역사 호환으로 통과하는 문제를 발견하여
정규화된 현행 필드 존재 여부로 구분하는 guard와 회귀 테스트를 추가했다. 현행 응답에서
raw 배열을 누락하면 `raw_contract_invalid`로 교정 대상이 된다.

한계 정보는 LabRun, 운영 분석의 승격 계획, 독립 검수 packet에도 보존한다. 검수 packet은
이를 원문과 구분된 모델 판단으로 전달하며, 검수 output schema에 한계 자체의 별도 verdict를
추가하지는 않았다. `prior_award` 지침은 행사·주최기관·기간·선정 범위·참가 횟수의 차이를
보존하고 근거 없는 조건 삭제·횟수 합산·답변 공용화를 금지한다.

계약 버전은 `deep-analysis-v30`, `lab-deep-v25`, `deep-analysis-validator-v18`이다.

단양의 과거 검수 packet과 입력 SHA를 확인한 1,443자 입력을 재사용했다
(구조화 843자·평가표 434자 및 입력 머리글). 당시 정규화된 조건 7개·축 22개로 응답을
재구성하고 새 구조적 한계만 합성해 다음을 확인했다.

| 응답의 한계 정보 | 매칭 준비도 | 기존 조건·축 | fake 모델 호출/교정 |
|---|---|---|---|
| 한계 미기록 | ready | 모두 보존 | 1 / 0 |
| 자격 상세 미확인, 영향 축 미특정 | conditional | 모두 보존 | 1 / 0 |
| 신청 절차만 미확인 | ready | 모두 보존 | 1 / 0 |

새 계약은 구조적으로 신고한 한계와 ready의 모순을 막는다. 모델이 한계 자체를 기록하지
않는 경우까지 자동으로 발견하는 완전성 검증은 아니다. 인용이 실제 입력에 있다는 것과
모델의 범위 판단이 의미적으로 옳다는 것도 구분한다. 새 실제 모델 결과는 아직 없다.

## 시간 비교의 해석

직전 실제 분석 wall은 249.660→262.366초로 5.1% 늘었다. RHWP 처리시간 합계는 줄었지만
primary와 병렬로 실행되어 전체 완료 시간을 줄이지 못했다. 이번 구현의 출력 중복 방지와
검수 정체 제한이 실제 품질 통과까지의 시간을 줄였다고 선언하려면 변경된 실행 계약에
결속된 후속 실측이 필요하다.

비교에서는 primary·RHWP·독립 검수 각각의 요청 수, 출력 토큰, 실행시간과 최종 품질 상태를
함께 기록한다. 병렬 시간을 단순 합산하거나 빠른 실패를 시간 개선으로 계산하지 않는다.
