# 등록정보 자동입력 의미 가드 검증

[실제 Studio probe](../evidence/native-autofill-20261001/2026-10-01T04-58-44-395Z/report.json)의 정상 alias mapping에서 홈페이지 주소가 `company_address`, 기업명(영문)이 `company_name`, 법인등록번호(사업자등록번호)가 `company_business_number`로 해석됐다. 기존 값이 있었던 칸은 보호됐지만, 빈 칸과 주소가 저장된 실제 프로필 조합에서는 현재 프로필 값과 의미가 다른 입력이 가능했다.

제품 `applicationProfileAutofill.ts`의 공통 의미 가드를 canonical key와 `mappedCompanyField` 판정보다 먼저 적용했다. 현재 프로필에는 URL, 영문 상호, 법인등록번호 정본이 없으므로 해당 라벨은 등록정보 자동입력에서 제외한다. 국문 회사명, 회사 우편 주소, 명확한 사업자등록번호는 유지한다.

`buildAutomaticProfileAutofillEntries`도 동일 가드를 거친다. 이전 broad alias가 만든 suggested/profile 답변이 있어도 진입 자동입력이 이를 우회하지 못한다. identity profile key의 지원 범위로 모든 자동 시드를 제한하지는 않으며, 직원 수 같은 기존 회사 속성 시드는 유지한다.

변경 helper의 서버 참조는 type-only이고 runtime import는 기존 `guideText`뿐이다. 분석·모델 호출 dependency를 추가하지 않았다. 실행 중 분석의 source 코드, 모델 산출물, precompute mapping과 스키마는 수정하지 않았다.
