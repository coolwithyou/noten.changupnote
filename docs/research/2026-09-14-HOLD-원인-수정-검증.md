## 딥분석: 서약 사실과 신청·평가 효과

일치시켰다. 검증기는 exact source span이 현재 입력에 결속된 뒤에만 제한적 의미 검사를
수행한다. 근거 없는 확대는 `semantic_misattribution`으로 수리를 요청하며 자동 삭제하지 않는다.
명시적 제외, 제외의 정상 예외, 영어 역량의 실제 평가·배점은 보존한다.

## 안성: 평가 정보 한계의 자기모순

안성의 기존 `sourceLimitations[2]`는 평가표·배점·가점 항목이 전혀 없고 선정 우선순위가
어떻게 결정되는지도 판단할 수 없다고 설명하면서 `evaluation_precision`으로 분류했다.
이 scope는 평가항목 또는 방향이 제공되고 숫자 배점·가중치만 미공개인 경우에 한정된다.

검증기는 exact source ref 검증 뒤 위 두 부재 진술이 함께 있는 제한적인 자기모순만 잡는다.
잘못된 항목을 자동으로 자격 한계로 재분류하지 않으며, 모델 설명을 원문 증거로 사용하지 않는다.
검증된 limitation 보존 목록에서 해당 항목을 제외하므로 보정 응답에서 제거된 오분류가 다시
삽입되지 않는다. 유효한 자격 한계는 계속 보존한다.

최종 코드의 실제 이전 응답 재검증에서 안성의 새 지적은 `$.source_limitations[2].scope`
한 건이고, 기존 자격·절차 한계 2개는 보존됐다. TECHFEST의 정상 `evaluation_precision`은
유지됐으며 단양에는 새 지적이 없었다. 별도 주입 모델 테스트에서는 보정 응답이 모든 한계를
누락해도 유효한 자격 한계만 복원되고 오분류는 복원되지 않아 matching conditional을 유지했다.

‘방향은 제공되지만 정확한 우선순위를 계산할 배점이 없음’, 한쪽 항목만 미제공인 경우,
‘없는 것은 아니다’, ‘없다는 뜻은 아니다’ 같은 정상 표현은 거부하지 않는 회귀를 통과했다.
독립 검토에서 발견한 OR 조건·직접 부정 오탐도 이 범위에 반영했다.

## RHWP: 병합 셀 값의 중복 후보와 미지원 이미지 입력

[이전 재측정 보고서](2026-09-14-개선배포후-동일3건-재측정.md)의 ‘라벨 셀 오추천 2개’는
parsed 좌표를 실제 쓰기 target으로 해석한 오류가 있어 정정했다.

| 후보 | 수정 전 실제 native target | 수정 후 |
| --- | --- | --- |
| 법인등록번호 | 올바른 오른쪽 값 셀, `parentPara=180`, `cell=17` | 정상 입력 유지, 실제 값 안내문을 보존 |
| 별도 ‘해당 시’ | 다른 항목의 라벨 셀, `parentPara=180`, `cell=14` | 앞 라벨의 값 안내문으로 소비된 중복 후보를 구조적으로 제외 |
| 이미지 | 오른쪽 중첩 이미지 host, `parentPara=182`, `cell=26` | 일반 텍스트 입력으로 추천하지 않고 지원되지 않는 구조 경고로 기록 |

KorDoc의 `c+1` 값 조회가 병합 라벨의 `colSpan`을 반영하지 않는 것이 중복 후보의 원인이었다.
수정은 IR에서 증명한 조건부 placeholder 관계에 한정한다. 일반 작성 예시를 이미 입력된 값으로
취급하면 기업명·아이템명·공동대표 등이 빠질 수 있어 전면 값 정규화는 적용하지 않았다.
중첩 표나 이미지 관련 라벨을 일괄 제외하지 않으며 정상 서술형·사진 제목 입력을 보존한다.
구조적으로 제외한 후보는 모델 판정 대상에서 빠져 반복 판정으로 다시 추천되지 않는다.

실제 TECHFEST IR의 결정적 추출을 수정 전후 비교한 결과 후보 93개와 ID는 유지되고,
위 3개만 값·추천·구조 신호가 바뀌었다. 기존 모델 판정을 재생성한 비교는 아니다.

같은 IR 후보에서 구독 모델의 경계 판정 대상은 45→42개로 줄었다. 정상 법인등록번호는
결정적 입력으로 처리하고, 중복 placeholder와 미지원 media는 모델에 보내지 않기 때문이다.
후속 contextual-region 후보를 제외한 비교이며 전체 요청 수·출력 토큰·wall time의 절감을
실측한 것은 아니다(`triage-work-comparison.json`).

원본 HWPX SHA `5d9ad6200091e341c945f1c746b1512ded6f2d85f0aa21bd6f0eac5b566fe22c`로
수정된 추출 → 제품 필드 변환 → 실제 `@rhwp/core` WASM anchor 해석을 실행했다.
세 후보 중 정상 법인등록번호만 필드로 노출됐고, 그 값 셀에 시험값을 입력해 저장·재열기 후
