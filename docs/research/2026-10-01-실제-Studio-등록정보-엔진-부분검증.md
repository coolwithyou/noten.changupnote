# 실제 Studio 등록정보 엔진 부분 검증

## 범위

2026-10-01 authoring-first에서 기존 원문과 분석 후보를 읽어 일반 등록정보 엔진을 로컬 검증했다. source HWPX SHA는 `ceb2c53a1a4ff825e3661deecd5a7533d23a4d55f2e82126a240b6de3f06e150`, 불변 analysis SHA는 `b2971cd397065570c440260f51a2eccabfa48eb079d403619e000feaba324732`다.

불변 분석은 raw 후보 89개 / accepted 66개이며, 저장된 admission은 `review_required`, `materialize=false`로 유지했다. 기존 `buildReconciledApplicationFields` pure consumer에서 accepted 66개를 projection했을 뿐 DB 필드·초안·승격 데이터를 만들지 않았다. 후보 ID도 로컬 식별자로만 사용한다.

## 정상 엔진 결과

실제 vendored `@rhwp/editor` → 자가호스팅 Studio → `resolveStudioFieldAgentProtocol` 경로로 원문을 열었다. 실제 RHWP binding과 evidence를 받아 기존 `buildApplicationProfileAutofillPlan`이 ready로 판정한 회사명 한 칸을 `createStudioProfileAutofillTransaction`으로 적용했다. 합성 profile은 회사명 `합성 검증 기업`, 대표자 `합성 대표`, checksum 형태의 테스트 사업자번호 `0000000000`이며 외부 검증에 보내지 않았다.

- 적용: 기업명 1개, 원문 block 5 / row 2 / col 2 (colSpan 4).
- native target: section 0 / parentPara 7 / controlIndex 0 / cellIndex 4 / paragraph 0.
- 실제 host command 영수증 검증, export, 재열기에서 unique binding과 `합성 검증 기업`을 확인했다.
- 514개 logical 표 좌표를 무편집 export와 비교해 변경은 위 값 셀 하나였다. 나머지 표 text/span은 동일했다.

이것은 기존 등록정보 dialog의 ready plan을 실제 transaction에 넣은 부분 엔진 검증이다. 최초 진입 자동입력은 별도 정상 seed/consumer로 계산한 결과 **0개**였다. 중복 표시 라벨과 현재 값 보호를 우회하지 않았다.

사업자번호의 두 mapping은 `already_filled`로 보호됐다. 대표자명 profileKey에 해당하는 필드는 0개였고, `성명` 네 필드는 신청인 이름으로 해석돼 대표자명으로 바꾸지 않았다. 따라서 회사명·대표자·번호 전체 자동입력이나 실제 운영 UI 성공을 선언할 수 없다. 새 분석의 문맥·필드 결속을 검수할 때 이 구분을 유지해야 한다.

## 재현과 검증

```bash
node tools/native-autofill-probe/run.mjs \
  spike-out/structural-gap-probe/source.hwpx \
  spike-out/analysis-lab/application-roundtrip/bizinfo__PBLN_000000000126841/roundtrip-2026-10-01T041138.341Z-800a5b/analysis.json
```

원문을 재확보할 때도 같은 source SHA를 먼저 확인한다. 실행은 유한 localhost 서버와 격리된 browser 세션을 종료한다. 임시 번들도 제거한다. source·모델 실행 코드는 수정하지 않았다.

- [최종 finite 실제 protocol/transaction probe](../evidence/native-autofill-20261001/2026-10-01T04-58-44-395Z/report.json): PASS. server/session/bundle 정리도 결과에 확인했다.
- `pnpm --filter @cunote/web exec tsc -p ../../tools/native-autofill-probe/tsconfig.json --noEmit`: PASS. 도구의 두 TypeScript entry와 import 경로를 검증했다.
- `git diff --check`: PASS.
- 첫 실행도 dialog 회사명 1개 적용은 PASS였으나 startup seed를 보고하지 않았다. 두 번째 실행은 server 전용 fieldAnswers를 브라우저에 import해 bundling에 실패했으며 증거를 덮어쓰지 않았다. server seed를 정상 Node prepare에서 실행한 후 최종 검증했다.

[실행 도구](../../tools/native-autofill-probe/README.md). 증거는 `docs/evidence/native-autofill-20261001/`의 개별 `report.json`에 source/analysis SHA, immutable admission, 자동 seed 결과, 실제 host receipt와 변경 셀을 함께 기록한다. 원본 HWPX·입력/출력 전체 bytes를 커밋하지 않는다.
