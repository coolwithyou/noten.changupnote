# 레거시 질문 제한 이관 writer 구현 검증

작성일: 2026-09-22

## 전체 계획 위치

- 실행 묶음: R2 — 소량 이관과 사용자 왕복 완결
- 이번 범위: R2-1 — 전용 원장, exact 적용 writer, 답변 보존 rollback
- 다음 범위: R2-2 — 기존 confirmation v2 경로에서 질문 노출·답변·관련 공고 반영·수정·철회·재진입

## 구현 경계

- `analysis_lab_promotion_releases`의 준비·승인 actor와 exact plan 결속은 재사용한다.
- 공고 전체를 교체하는 `analysis_lab_promotion_items` writer는 사용하지 않는다.
- 질문별 before/after snapshot과 operation SHA를 `analysis_lab_legacy_question_migration_items`에 기록한다.
- 공고 ID를 정렬해 transaction advisory lock을 획득하고 source·criterion·legacy 질문·답변 수를 잠금 뒤 다시 확인한다.
- legacy 질문 비활성화, v2 successor 생성, confirmed dedup component의 `match_state` 삭제, item receipt와 release 상태 전진은 한 transaction이다.
- rollback은 successor 답변이 0건이고 after snapshot이 일치할 때만 실행한다. successor는 삭제하지 않고 rollback 이력으로 비활성화한다.

## 검증 증거

`pnpm test:product-postgres`

- 폐기용 Unix socket PostgreSQL cluster만 사용했다.
- migration 89개를 빈 DB에 순서대로 적용했다.
- 준비 멱등성과 준비자/승인자 분리를 확인했다.
- 적용 및 재시도, 다른 질문·criterion 보존, confirmed dedup component의 match state 무효화를 확인했다.
- legacy 질문에 답변이 생긴 baseline drift에서 적용 전체가 원복되는 것을 확인했다.
- migrated v2 질문에 답변이 생긴 뒤 rollback이 중단되고 release/item 상태와 답변이 보존되는 것을 확인했다.
- 답변이 없는 경우 legacy 질문 복구와 successor 이력 비활성화, rollback 재시도를 확인했다.
- 일반 product role이 전용 원장을 읽지 못하는 FORCE RLS 경계를 확인했다.

`pnpm --filter web typecheck`

- 새 schema, writer, fixture의 TypeScript 계약을 확인했다.

## 아직 하지 않은 일

- 운영 DB migration 적용
- 사람 검수 결정 또는 release 승인 생성
- 실제 공고 질문 이관
- 배포와 로그인 사용자 브라우저 검증
- R2-2의 답변 수정·철회·관련 공고 반영 화면 인수

따라서 이번 결과는 적용 가능한 제한 writer의 구현·격리 검증이며 운영 이관 완료가 아니다.
