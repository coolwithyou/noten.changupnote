# 조건 해소 중심 전환 1차 구현 검증

작성일: 2026-09-22

기준 소스: `526283d` (`origin/main`)

구현 브랜치: `codex/condition-resolution-transition`

## 이번 범위

- 조건의 근거 상태, 해소 주체, 질문 필요 여부, 재사용 범위를 한 순수 계약으로 분리했다.
- 검수된 조건에서 질문 수요를 직접 계산한다. 과거 promotion plan의 질문 목록을 수요 정본으로 사용하지 않는다.
- 분석 없음, 현행 원문 결속 누락, 조건 검수, 질문 준비, 원문 변경을 서로 다른 다음 작업으로 분리했다.
- 조건 행이 이미 있으면 발행 증거가 없다는 이유만으로 `analysis_missing`으로 되돌리지 않는다.
- 구조화 조건은 기존 matcher가 실제로 회사 프로필과 비교할 수 있을 때만 회사 정보 입력으로 보낸다.
- 같은 사업장 사실을 쓰는 네 공고와 범위·기준일이 다른 두 공고의 재사용 경계를 회귀 사례로 고정했다.
- matching campaign 준비도 같은 다음 작업을 읽는다. `condition_analysis`만 모델 준비 후보로 남기고 검수·질문·자료 복구·원문 변경은 원인별 비실행 상태로 봉인한다.

## 읽기 전용 현행 대조

동일한 2026-09-22 지원기간 유효 공고 537건을 운영 DB의 repeatable-read/read-only transaction으로 비교했다.

| 분류 | 기존 | 1차 구현 |
| --- | ---: | ---: |
| 완전 준비 A | 7 | 0 |
| 질문 준비 B | 0 | 5 |
| 조건 구조·검수 C | 2 | 296 |
| 원문·분석 D | 528 | 236 |

새 다음 작업은 다음과 같이 분해됐다.

| 다음 작업 | 건수 | 모델 실행 |
| --- | ---: | --- |
| 실제 조건 분석 | 194 | 필요 |
| 원문 변경 영향 검토 | 42 | 기본 불필요 |
| 기존 조건·결속 검수 | 296 | 불필요 |
| 질문 준비 | 5 | 불필요 |
| 자료 복구 | 0 | 불필요 |
| 즉시 재사용 | 0 | 불필요 |

기존 A 7건도 조건에서 다시 계산한 질문 수요와 구조 지원 여부를 통과하지 못해 그대로 유지하지 않았다. 이는 기존 숫자를 보존하기 위한 분류가 아니라, 사용자에게 실제로 답할 수 있는 질문과 현행 근거가 있는지를 기준으로 한 결과다.

첨부가 있는 공고의 현재 input manifest는 DB inventory만으로 재생성할 수 없다. R2 전문과 변환 결과를 다시 봉인하지 않은 채 과거 분석 manifest를 현재값으로 복사하지 않는다. 이 경계는 후속 coverage/변경 영향 작업에서 다룬다.

## 남은 경계

- 구조화 회사 프로필 답변은 이미 여러 공고에 재사용되며, 사업장 범위와 기준일도 matcher가 분리한다.
- `grant_confirmation_questions.reusable=company_fact`의 답변 저장은 아직 `(company, grant)` 범위다. 임의 condition key를 곧바로 전역 사실로 승격하지 말고, 기존 profile fact로 표현 가능한지와 의미·기준일·철회 계약을 먼저 확정해야 한다.
- coverage 변경 영향, 기존 자산 이관, 신규 유입 전향 인수는 후속 단계다.
