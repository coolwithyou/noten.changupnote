# Native 라벨 순번과 입력 셀 결속 안전 검증

현재 완료 분석 `roundtrip-2026-10-01T050056.268Z-98c796`의 66개 추천 필드를 정상 `buildReconciledApplicationFields → resolveStudioFieldBindings` 경로로 원문에 대조했다. 운영에서 관측한 위치 확인 62/66을 재현했으나, unique라는 결과만으로 정확한 입력 위치를 보장하지 못하는 일반 resolver 결함을 확인했다.

원문 SHA: `ceb2c53a1a4ff825e3661deecd5a7533d23a4d55f2e82126a240b6de3f06e150` (127513 bytes). 불변 분석·승격 산출물은 수정하지 않았다. 모델 호출 및 운영 DB/API 쓰기 없이 원문과 이미 다운로드된 파일을 읽었다.

## 재현과 원인

원문 첫 신청 표의 달러 셀들은 최근 3개년 실적의 숫자 값 셀이다. 기존 source에는 해당 단위 셀을 `anchorLabel`로 저장했으나 명시된 `table_cell_text` target 계약이 없다. resolver는 이 라벨의 오른쪽/아래 셀을 대상으로 추정했다. 추가로 원문 라벨 occurrence를 입력 대상이 남은 후보 배열에 적용해, 제외된 셀 때문에 뒤의 연도·행으로 이동했다.

| 필드 | 분석의 원문 행,열 | 기존 native target 행,열 |
| --- | --- | --- |
| 직접 수출액 2024 | 13,4 | 13,7 |
| 직접 수출액 2025 | 13,7 | 13,9 |
| 간접 수출액 2024 | 14,4 | 14,7 |
| 간접 수출액 2025 | 14,7 | 15,9 |
| 합계 수출액 2024 | 15,4 | 16,9 (근무인원) |

합계 2025의 occurrence 7은 필터 후 후보 수 7을 벗어나 ambiguous였다. 다른 미확인 3개는 전체 너비 제목 `사업계획서`, 오른쪽 값 셀 안내문 두 개였다. 안내문 두 개에는 이미 왼쪽의 현지 시장 진출 현황/경력 및 고객 설정 사유 항목이 존재한다. 안내문 자체를 다시 라벨로 삼아 다른 셀에 쓰는 것은 안전하지 않다.

## 일반 수정

- 원문 전체의 normalized whole-cell exact 라벨을 먼저 구조 순서로 중복 제거하고 occurrence를 선택한다. 대상 셀이 없어도 원문 순번에서 빠지지 않는다.
- source row/col이 있으면 선택한 native 라벨 셀의 행·열과 대조한다. 일치하지 않으면 missing으로 종료한다.
- 숫자 필드의 단위만 적힌 라벨에는 오른쪽/아래 추정을 적용하지 않는다. 해당 셀을 직접 쓸 권한은 명시된 same-cell target 좌표와 whole-cell exact가 함께 증명할 때만 연다.
- 보호된 장문 영역은 기존 target 좌표와 첫 문단 prefix 증명 계약을 유지한다. 원고가 붙은 셀의 whole-cell occurrence로 대체하지 않는다.
- 필터 후 대상 배열에 occurrence를 적용하는 tie-break를 제거했다. 복수 구조 target은 ambiguous를 유지한다.

현재 산출물에서는 52/66이 unique, 14개가 missing이다. 제외는 단위 숫자 8개, 제목·중복 안내문 3개, 오른쪽 끝의 `(향후 1년 이내)` 값 셀 두 개(명시 same-cell 계약 없음), 투자유치 선택 필드 1개(analysis 위치가 라벨 대신 checkbox 값 셀)다. 정확한 입력 대상으로 열려면 정상 분석/구조 계약에서 target 의미를 증명해야 한다. 이 변경으로 완전한 분석 또는 전체 66개 쓰기 가능을 선언하지 않는다.

## 운영 등록정보 다운로드 대조

일반 UI가 이미 저장하고 다운로드한 `/tmp/cunote-demo-20261001/singapore-autofill.hwpx`를 read-only 비교했다. SHA `47ef0224f1c6acd2cf898076e8a779534f90ff33940edc9f81ac9d575d7b4904`, 99411 bytes.

원문을 같은 native 엔진으로 무편집 export한 baseline과 비교하여 514개 IR 셀 중 19개 차이를 확인했다. 그중 18개가 회사명 startup 입력 1개와 등록정보 UI 입력 17개(주소 1, 성명 4, 이메일 4, 전화 8)다. 각 입력은 해당 라벨의 값 셀에 있고 모든 rowSpan/colSpan이 보존됐다. 나머지 차이 1개는 알려진 자간 공백 정규화이며 내용은 같다. 나머지 495개 셀은 보존됐다.

회사명은 block5,row2,col2, 본점 주소는 block1,row6,col7, 성명/이메일/전화는 각 라벨 옆 값 셀에 들어갔다. 기존 사업자번호 template, 홈페이지, 영문 회사명, 법인등록번호에는 변경이 없다. 이 대조는 실제 선택 프로필의 모든 값 자체를 서버 원장과 재검증한 결과는 아니며, 다운로드 결과의 입력 위치·나머지 셀 보존 증거다. 이름/연락처 값은 문서에 복제하지 않았다.
