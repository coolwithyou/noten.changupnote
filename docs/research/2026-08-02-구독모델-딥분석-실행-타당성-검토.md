# 구독 모델(Claude Max / Codex Pro)로 로컬 딥분석 실행 — 타당성 검토

- 날짜: 2026-08-02
- 질문: 운영 API 토큰 경로는 그대로 유지하면서, 로컬 대량 딥분석만 사용자의 LLM 구독(Claude Max 20x, Codex Pro)으로 실행해 동일 로직으로 공고 필드를 채울 수 있는가?
- 조사 방법: 코드 전수 매핑(호출부·데이터 계약·파급 범위) + 로컬 CLI 실측 프로브(claude 2.1.219, codex 0.146.0)

## 결론

**가능하다 — Claude Max 경로는 조건부 GO, Codex Pro 경로는 본선 부적합(실험 레인만).**

핵심 근거: 딥분석의 LLM 호출은 `apps/web/src/lib/server/deep-analysis/extractor.ts`의 `runDeepGrantAnalysis()` 단일 함수이고, 이 함수는 이미 `fetchImpl?: typeof fetch` 주입 파라미터를 갖고 있다(extractor.ts:93). **Anthropic Messages API 요청을 `claude -p` 호출로 번역하고 응답을 Messages API 형태로 재조립하는 fetch 호환 shim 하나만 만들면, 추출·정규화·span 검증·게이트·승격 로직을 단 한 줄도 바꾸지 않고 백엔드를 교체할 수 있다.** "딥분석과 동일한 로직으로 필드를 채운다"는 요구가 구조적으로 충족된다.

## 1. 왜 구조적으로 가능한가

### 1-1. 전송층이 단일 심(seam)으로 이미 분리돼 있다

- `@anthropic-ai/sdk`는 딥분석 파이프라인에 전혀 없다. 모든 호출은 원시 `fetch("https://api.anthropic.com/v1/messages")`.
- 딥분석 계열의 LLM 호출 모듈은 정확히 2개:
  1. `deep-analysis/extractor.ts` — `runDeepGrantAnalysis` (운영 worker + dev lab 공용)
  2. `analysis-lab/ai-review.ts` — `callAnthropicToolModel` (ai-review / ai-audit / confirmations가 재사용, **lab 전용으로 격리됨**)
- **모든 호출부가 `fetchImpl?: typeof fetch`를 받는다** (테스트 페이크 주입용으로 이미 설계됨). 이것이 드라이버 주입점.
- chat·matching·ingestion·credits는 lab과 어떤 클라이언트 모듈도 공유하지 않는다. 유일한 공유 파일은 `deep-analysis/extractor.ts`(운영 딥분석 워커와 공유) — 따라서 **스위치는 extractor 내부가 아니라 호출자(analyze.ts 등)에서 fetchImpl을 넘기는 방식이어야 운영 무영향**.

### 1-2. 검증 로직이 백엔드 불가지론적이다

"응답 불신 원칙"에 따라 enum 밖 값 드롭, confidence 클램프, source_span 원문 실재 검증(`verifySpan`)이 전부 **전송과 무관한 export 순수 함수**로 분리돼 있다(`normalizeCriteria`, `normalizeAxisAssessments`, `verifySpan` 등). CLI가 뱉은 JSON에도 그대로 적용된다. `inputSha256`·`spanVerified` 검증은 입력 텍스트 기준이라 백엔드 교체와 무관하게 유지된다.

### 1-3. lab 경로는 metering(운영 원가수집)에 애초에 안 걸린다

`extractor.ts:8-10` 주석에 의도적 설계로 명시: 실험 비용이 서비스 원가로 오염되지 않도록 metering 래퍼 사용 금지, `costPolicy.priceDeepAnalysisUsage`로 직접 계산만 한다. 즉 백엔드를 바꿔도 크레딧 원장이 어긋날 것이 없다.

## 2. CLI 실측 결과 (2026-08-02, 이 머신)

### claude CLI 2.1.219 — 구독(Max) 과금 확정

- 인증: 셸에 `ANTHROPIC_API_KEY` 없음. macOS Keychain의 OAuth 토큰(subscriptionType: **max**, sw@noten.im) 사용 → **호출은 Max 구독 사용량으로 소진, API 과금 아님**.
  - 주의: JSON 출력의 `total_cost_usd`는 구독이어도 명목 계산치가 찍힌다. "비용 0 = 구독" 판별법은 성립하지 않음. `--bare` 모드는 반대로 OAuth를 안 읽고 API 키만 쓰므로 **구독 실행 시 --bare 금지**.
- 실측: `claude -p '<프롬프트>' --output-format json --model sonnet` → 11초, 단일 JSON 반환, `result` 필드에서 내부 JSON 완벽 파싱.
- 유효 플래그: `--json-schema <schema>`(구조화 출력 강제 — **미실측, 구현 1단계에서 실제 22축 스키마로 검증 필요**), `--system-prompt`(기본 시스템 프롬프트 대체), `--tools ""`(빌트인 도구 전부 차단), `--effort low~max`(API의 output_config.effort 대응), `--max-budget-usd`, `--no-session-persistence`, `--strict-mcp-config`, `--fallback-model`.
- 함정: ① 2.1.219에 `--max-turns` 없음 → `--max-budget-usd`로 대체. ② macOS에 `timeout` 바이너리 없음 → Node `execFile`의 timeout 옵션 사용. ③ 프로젝트 디렉터리에서 실행하면 CLAUDE.md·MCP가 로드됨 → **깨끗한 스크래치 cwd에서 실행**. ④ 호출당 오버헤드 ~10초 콜드스타트 + 하네스 시스템 프롬프트 토큰(--system-prompt·--tools "" 로 상당 부분 축소 가능) — 딥분석은 호출당 수 분짜리라 무시 가능.

### codex CLI 0.146.0 — ChatGPT 구독 인증 확정

- `codex exec --json --output-schema <file> -o last.txt` 실측 통과: JSON 스키마 강제 출력이 실제로 동작(6~7초, claude보다 가볍고 빠름).
- 함정: stdin이 열린 파이프면 행 위험 → `< /dev/null` 필수. `--ephemeral`·`--ignore-user-config`로 격리 권장.

## 3. 리스크와 대응 (dataflow 계층 정밀 분석)

| # | 리스크 | 대응 |
|---|--------|------|
| 1 | **usage/costUsd 소실 → 게이트 허위 통과.** CLI가 usage를 안 주면 `normalizeUsage`→null→`aggregate`의 costPerNotice=0으로 $1 게이트 무의미 통과, `--max-cost-usd` 상한도 무력화 | claude CLI JSON은 usage(input/output/cache_read)를 반환한다. shim이 이를 Anthropic usage 필드명으로 매핑하면 기존 가격표로 **명목 비용이 그대로 계산돼 게이트 의미 보존**(실지출 0은 문서화) |
| 2 | **모델 id 문자열 결속.** 가격표(costPolicy)·순환 가드(판정모델==추출모델 throw)·AI검수 파일 키(`.ai-review.claude-fable-5.json`)·`AI_REVIEW_ADOPTED` 캘리브레이션 상수가 전부 정확한 `claude-*` id 키 | shim이 `--model`에 **allowlist의 풀 모델 id를 그대로 전달**하고 run.model에도 그대로 기록. 별칭(sonnet/opus) 사용 금지. CLI의 `modelUsage` 키로 실행 모델 일치 검증 |
| 3 | **run.model은 요청값 echo** — 래퍼가 내부에서 모델을 바꾸면 provenance 조용히 오염 | shim에서 CLI 응답의 modelUsage 키 ≠ 요청 모델이면 throw |
| 4 | **행동 동등성.** `--system-prompt`로 대체해도 CLI 하네스가 API 원시 호출과 바이트 동일하진 않음. ai-review-v2 캘리브레이션(24/28)은 API 경로에서 측정된 것 | 채택 전 **동일 공고 N건 API vs CLI A/B 섀도 비교**(기존 lab 문화 그대로: diff criteria → aggregate). LabRun에 `transport` provenance 필드 추가해 혼입 방지 |
| 5 | **파라미터 정책.** Opus 4.8/Fable 5는 temperature/thinking 전송 시 400 | CLI는 애초에 sampling 파라미터를 노출하지 않음 — 오히려 정책과 정합. effort는 `--effort high`로 대응 |
| 6 | **Max 사용량 한도.** 5시간 롤링 윈도 + 주간 상한. 딥분석 입력은 큼(최대 800k chars 캡) | 대량 배치는 sonnet-5 우선, 청크 실행. batch.ts의 재개 설계(spike-out 전수 스캔 스킵)가 이미 중단-재개에 안전해 윈도 넘김 운용 가능 |
| 7 | **약관.** 구독을 프로덕션 서비스 백엔드로 쓰는 것은 불허 | 정확히 사용자가 의도한 분리와 일치: **운영 worker는 API 유지, 로컬 dev 배치만 구독**. env 스위치를 lab 오케스트레이터에서만 읽게 해 구조적으로 강제 |

## 4. Codex Pro 경로 판정: 본선 부적합

기술적으로는 동작하지만(§2 실측), 계약 전체가 Anthropic 모델에 결속돼 있다:

- 모델 allowlist(`DEEP_ANALYSIS_PRIMARY_MODELS` = claude-opus-4-8, claude-sonnet-5)와 `assertDeepAnalysisModelEffort`가 **extractor 호출 시점에 throw**
- 가격표·파일 키·순환 가드·캘리브레이션 상수 전부 `claude-*` id
- GPT 계열 산출물은 기존 캘리브레이션과 비교 불가능

→ 딥분석 필드 채움 본선에는 쓸 수 없고, **allowlist 밖 별도 실험 레인**(예: 교차 검증·세컨드 오피니언 감사 실험)으로만 의미 있음. 도입하려면 계약 확장 + 재캘리브레이션이 선행돼야 한다.

## 5. 제안 설계 (구현 시 청사진)

```
apps/web/src/lib/server/deep-analysis/transport-claude-cli.ts   (신규, ~1파일)
  export function buildClaudeCliFetch(opts?): typeof fetch
  - 입력: Messages API 요청 body(JSON) → model, system, messages, tools[0].input_schema, tool_choice 해석
  - 실행: execFile("claude", ["-p", <user content>, "--output-format","json",
           "--model",<full id>, "--system-prompt",<system>, "--tools","",
           "--json-schema",<input_schema>, "--effort",<effort>, "--no-session-persistence"],
           { cwd: <빈 스크래치 디렉터리>, timeout: <기존 540s 정책> })
  - 출력: CLI JSON → { content:[{type:"tool_use", name:<tool명>, input:<파싱 JSON>}],
           stop_reason:"tool_use", usage:{input_tokens, output_tokens, cache_read_input_tokens} }
           형태의 Response로 재조립 → 기존 파싱·정규화 경로가 그대로 소화
  - 가드: modelUsage 키 ≠ 요청 모델이면 throw / --json-schema 실패 시 프롬프트-JSON + 기존 정규화 + 1회 재시도 폴백
```

- **스위치**: env `ANALYSIS_LAB_TRANSPORT=claude-cli`를 **lab 호출자에서만** 해석(`analysis-lab/analyze.ts`가 fetchImpl 전달 + `resolveAnthropicApiKey` 스킵). 운영 worker(`deep-analysis:worker`)는 이 env를 읽지 않으므로 원천적으로 무영향.
- **사이드카 레인 재사용**: ai-review/ai-audit/confirmations도 같은 shim을 fetchImpl로 받으면 AI 검수·감사·질문 보강까지 구독으로 실행 가능(모델 id는 기존 그대로: fable-5 검수, sonnet-5 감사).
- **provenance**: LabRun contract에 `transport: "api" | "claude-cli"` 필드 추가(기존 run은 undefined=api). 승격 게이트는 model 문자열 기반이므로 model은 실제 id 그대로.
