# 매칭 행동 개선 1차 구현 검증

작성일: 2026-09-20 KST

## 범위와 상태

사용자의 구현 시작 지시에 따라 [개선 계획](../plans/2026-09-20-매칭-이해와-다음행동-개선계획.md)의 W0 기준선, W1~W4 첫 구현과 W5 일부 검증을 수행했다. 기준 소스는 HEAD `8668796` 위 작업 트리이며 커밋·push·배포하지 않았다. 기존 무관한 문서 변경은 보존했다.

W0은 Sol high, W2/W3 UI는 Sol high 에이전트가 담당했다. 공유 설명 계약과 W4 질문·피드백 통합은 주 에이전트가 수행했다. W4는 계획의 별도 Sol xhigh 위임 대신 공유 계약·브라우저 피드백과 함께 직접 통합했다.

## 구현

- W1: `packages/core/src/use-cases/match-explanation.ts`에 판정을 변경하지 않는 공통 조건 설명과 행동 선택을 추가했다. 충족·미충족·미확인과 회사 정보/공고 확인 원인을 분리하고 카드 수준 검토 gate를 보존한다.
- W2: 결과 상단을 실제 후보 탐색 중심으로 바꿨다. 단순 후보를 관련성 높은 맞춤 추천으로 표현하지 않으며 목록에는 표시 중인 수를 쓴다. 분석 범위·전체 기업정보 현황은 결과 아래 접힘 영역으로 이동했다.
- W3: 카드와 상세에서 모든 필수·제외 조건의 공고 원문, 회사 값, 판단 이유와 행동을 표시한다. 우대조건은 별도로 다룬다. 원문 구절을 우선하여 OR 문맥이 요약 과정에서 사라지지 않게 했다.
- W4: 원문 확인과 회사 정보 부족이 섞인 공고에서도 검수된 입력 가능 조건을 질문으로 제공한다. discovery·마감·미검수 조건은 이 경로에서 제외한다. 답변으로 전체 자격이 확정된다고 약속하지 않고 남는 공고 확인 수를 전달한다.
- W4: 카드의 특정 항목에서 해당 입력을 연다. 현재 질문과 같은 항목이면 서버가 제공한 정확한 질문·선택지를 사용한다. 답변 영향은 동일 원문 revision·동일 조건 ID에 한해 부분 해소로 집계한다.
- DTO/OpenAPI: 선택 필드 `sourceReviewRemainingGrantCount` 추가 및 생성 스키마 갱신.

## 브라우저 흐름

기존 실행 중인 `127.0.0.1:4010` 서버를 사용했으며 새 개발 서버를 시작하지 않았다. 익명 합성 회사로 검사했다. 이 환경은 discovery flag가 꺼져 평가 49건·표시 8건인 경로로, 전체 공개 공고 1,508건 경로와 다르다. 모집단 근거는 [기준선](2026-09-20-매칭-행동개선-기준선.md)에 분리했다.

1. 결과 상단에서 “살펴볼 공고를 찾았어요”와 다음 질문을 확인했다.
2. 한·독 바이오·헬스케어 세미나에서 필수조건 3개를 펼쳤다.
3. 신청대상 입력으로 이동해 현재 질문의 “일반기업”을 답했다. 일반 기업 형태만 묻던 입력 연결의 한계를 발견하여 정확한 질문 선택지로 수정한 뒤 재검증했다.
4. 해당 카드가 **충족 확인 0 / 미확인 3 → 충족 확인 1 / 미확인 2**로 바뀌었다. 남은 원문 확인은 유지되고 전체 지원 가능으로 잘못 승격되지 않았다. 다음 질문은 기업규모로 진행했다.
5. 데스크톱 1280px 및 모바일 390px 화면을 확인했다. 모바일 `scrollWidth=clientWidth=390`으로 가로 넘침이 없었고 원문 조건이 줄바꿈되어 표시됐다.

세션 화면: `/tmp/cunote-match-action-desktop.png`, `/tmp/cunote-match-action-card.png`, `/tmp/cunote-match-action-mobile.png`. 실제 사용자 로그인·저장 회사 흐름과 사람 대상 이해도 UAT를 대체하지 않는다.

## 남은 작업

- W5: 기존 landing-events endpoint는 수신 응답만 반환하고 영속 계측을 하지 않는다. 운영 전환율을 측정했다고 주장할 수 없으며 이벤트 저장·집계 경로가 남아 있다.
- 계획의 전체 뷰포트·키보드·인증 복귀·로그인 pagination 브라우저 인수는 아직 전부 수행하지 않았다.
- W6: OR/AND 복합 조건의 의미 판정 및 회귀 표는 미구현이다. 이번 원문 표시 보존을 복합 조건 해결로 간주하지 않는다.
- W7: 원문 검수·확인 질문 공급 개선은 미실행이다. 새 LLM 분석·서비스 데이터 승격은 없었다.
- W8: Preview·Production 반영 및 실제 사용자 효과 측정은 미실행이다. 실제 자격 충족 공고 수가 늘었다는 근거는 아직 없다.

이 변경은 후보 탐색과 미확정 이유·다음 행동을 개선한 첫 단계다. 운영 적용 완료나 전체 W0~W8 완료를 의미하지 않는다.
