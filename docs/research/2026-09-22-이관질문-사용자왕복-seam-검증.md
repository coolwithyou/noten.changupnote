작성일: 2026-09-22

## 전체 계획 위치

- 실행 묶음: R2 — 소량 이관과 사용자 왕복 완결
- 이번 범위: R2-2a 서버 왕복, R2-2b 브라우저 컴포넌트 왕복, R2-2c 인증된 격리 Next runtime·PostgreSQL·실제 화면 UAT
- 다음 범위: R3 분류 결과를 실제 최소 처리 adapter와 readiness 재평가에 연결

## 서버 왕복

R2-1 제한 writer가 만든 v2 질문을 별도 SQL 답변 삽입 없이 제품 서비스 함수로 처리했다.

1. `listGrantConfirmations`가 migrated 질문과 exact binding을 반환한다.
2. `submitGrantConfirmations`의 `yes`가 회사 사실을 만들고 현재 공고와 같은 의미의 독립 공고 3건을 함께 재계산 대상으로 잡는다.
3. 관련 공고의 읽기 결과가 `satisfied`와 `reusedFromCompanyFact=true`를 반환한다.
4. 같은 질문을 `no`로 수정하면 네 공고의 투영이 `unsatisfied`로 바뀐다.
5. `withdrawGrantConfirmation` 뒤 관련 공고에서 투영 답변이 사라진다.
6. 철회 이력도 사용자 답변이므로 migration rollback은 `post_migration_answers_present`로 중단하고 원장을 보존한다.
7. 별도 무답변 fixture만 제한 rollback에 성공한다.

검증: `pnpm test:product-postgres`. 빈 Unix socket cluster에 migration 90개를 적용했고 외부 DB를 사용하지 않았다.

## 브라우저 컴포넌트 왕복

- `pnpm test:inline-grant-confirmation-browser`: exact 질문 PUT, 저장 뒤 같은 카드 결과, 관련 공고 4건 갱신 안내, 결과 focus, 명시적 신청 준비 행동을 확인했다.
- `pnpm test:confirmation-sheet-browser`: 기존 답변 복원, 권한 변경과 stale 응답 차단에 더해 “여러 공고에 적용된 이 답변 철회” 행동이 exact question ID, answer revision, company-fact revision을 DELETE에 싣는지 확인했다.
- 두 테스트 모두 `about:blank`의 로컬 번들과 mock fetch를 사용했으며 외부 쓰기는 0건이다.

## R2-2c 인증 화면 인수

- migration item이 기존 promotion parent와 적용 전·후 serving hash를 보존한다.
- reader는 활성 release, 유일한 활성 parent, 최신 successor hash, 현재 공고 snapshot, migrated question·criterion·grant가 모두 일치할 때만 일반 promotion 결과 대신 successor를 허용한다.
- 이관된 `company_fact` 질문은 일반 질문 provenance만으로 열리지 않는다. exact 이관 원장이 검증된 경우에만 matcher의 3상태 질문으로 들어간다.
- 답변이 회사 사실로 투영돼 조건이 충족 또는 미충족된 뒤에도 exact 질문 연결을 유지해 카드의 “확인 내용 수정” 진입이 사라지지 않는다.
- 격리 fixture는 실제 제한 writer를 prepare→approve→apply하고, 인증된 HTTP 왕복으로 긍정·부정·철회와 관련 공고 4건 투영을 먼저 검증한다.
- 실제 브라우저는 password 로그인 후 공고 카드 inline 질문, 긍정 답변, 4건 안내, 지원 가능 전환, 신청 준비 이동, 수정 진입, 인증된 부정 변경·철회, 철회 뒤 inline 질문 재노출을 확인했다.

검증 명령은 `pnpm --filter web typecheck`, `pnpm test:grant-product-readiness`, `pnpm test:product-postgres`, `pnpm test:confirmation-natural-guards`, `node tools/run-local-product-uat.mjs --hold-seconds=180`, `node tools/product-uat/migrated-question-browser.mjs --connection=<private fixture connection>`이다. 최종 브라우저 receipt는 `status=passed`, `relatedGrantCount=4`, `deleteStatus=200`, `modelCalls=0`, `externalWrites=0`이었다.

현재 결과는 실제 사용자 화면까지 격리 환경에서 증명한다. 운영 schema 적용, 실제 공고 이관, 배포, 모바일 화면 인수는 포함하지 않는다.
