# 레거시 질문 이관 검수 packet 구현 검증

## 목적

read-only shadow에서 분리한 legacy 질문 후보를 현재 공고 원문 revision, criterion, 기존 질문 정의에
exact 결속한다. 사람은 이 packet으로 원문 조건, 질문 의미, 평가 극성, 답변 공유 범위를 검수한다.
packet 자체는 v2 질문을 만들거나 서비스에 반영하지 않는다.

## 원 계획과의 정렬

이 구현은 `2026-09-21-마지막조건-즉시확인-구현계획.md` P4의 검수 입력 준비 단계다.

- P1~P3의 사용자 카드·답변·재판정 계약을 변경하지 않았다.
- P4의 기존·신규 공통 readiness와 legacy shadow 분류를 그대로 입력으로 사용한다.
- 기존 LabRun 검수자를 발명하거나 DB legacy 질문을 기존 draft packet으로 위장하지 않는다.
- 사람 결정 이후 승인 후보만 기존 deterministic draft/release 경로로 연결한다.
- 미검수 질문 발행, 자동 migration, 서비스 DB 쓰기, 모델 호출은 수행하지 않는다.

## packet 계약

각 질문은 별도 content-addressed packet으로 생성된다. packet은 다음을 포함한다.

- shadow schema, snapshot SHA, 관측 시각
- 공고 ID·제목·수집원·지원기간·원문 URL
- 현재 source revision/raw SHA
- legacy 질문 ID·definition SHA·version·prompt·options·reusable·condition key·provenance
- criterion ID·stable key·dimension·kind·operator·value·source span·검수 상태
- 답변 원문을 제외한 기존 답변 수량
- 허용 verdict와 미작성 decision template

승인 결정은 packet/candidate/grant/question/criterion exact binding, 사람 검수자 이메일, canonical 검수
시각을 요구한다. `approve_for_v2_draft`는 criterion kind에서 파생한 극성과 사람이 고른
`per_notice | company_fact` scope가 모두 있어야 한다. `repair_criterion | retire_legacy_question`에는
승인 극성이나 scope를 기록할 수 없다.
