# 매칭 HOLD 영향도 분리 및 기존 산출물 재분류

작성일: 2026-09-19 KST
성격: 기존 로컬 증거의 읽기 전용 진단. release 승인·서비스 반영·신규 모델 실행 권한이 아니다.
구현 정본: [전체 매칭 실행계획](../plans/2026-09-18-전체-매칭-전환-및-토큰최적화-실행계획.md)의 2026-09-19 후속 절.

## 결론

검수 지적을 곧바로 공고 전체 HOLD로 연결하는 launch 경로와, 가점만 제외할 수 있는 기존 promotion 위험도 정책이 분리돼 있었다. 검수는 원시 추출 criteria를 보지만 실제 서비스는 정규화된 projection을 사용한다. 두 불일치를 우선 수정한다. 복잡한 OR 자동 판정 엔진이나 새 검수 레인은 추가하지 않는다.

기존 검수 140건은 PASS 56 / HOLD 84다. 이는 9월 18일 해당 실행의 결과이며 오늘 지원 가능한 공고 수·분석 오류율·서비스 공급 수가 아니다. exact19 원 코호트는 포함하지 않는다.

## 오프라인 분류 결과

manifest·aggregate 파일명의 SHA-256과 실제 bytes, receipt SHA, packet SHA, run SHA 및 grant 결속을 읽기 전용으로 대조했다. 검수 대상인 manifest.packets만 분모로 삼았고, 같은 receipt 안의 미검수 heldAudit 이력을 더하지 않았다.

분류는 상호 배타적이며 다음 순서다: 지적 없음 → 자격 영향으로 명시된 빈 축 누락 있음 → criterion 지적 있음 → ranking 빈 축 누락만 있음 → 그 밖의 영향 미확정. 설명문 키워드로 지적을 자동 무효화하지 않았다.

| 실행 | 검수 대상 | 기존 PASS | 자격 누락 지적 있음 | criterion 영향도 추가 근거 필요 | ranking 축 누락만 있음 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 신규 initial | 95 | 42 | 6 | 46 | 1 |
| 신규 retry | 4 | 3 | 0 | 1 | 0 |
| 신규 child1 | 11 | 2 | 2 | 7 | 0 |
| 기존 18 | 18 | 6 | 2 | 10 | 0 |
| 기존 12 | 12 | 3 | 1 | 8 | 0 |
| 합계 | 140 | 56 | 11 | 72 | 1 |

- 11건은 검수자가 eligibility 누락을 지적한 집합이다. 이번에 모든 지적을 사람이 실제 오류로 확정했다는 뜻은 아니다. 다른 criterion 지적이 겹칠 수 있다.
- 72건은 역사 criterion 지적에 구조화된 영향도가 없어서 자동 면제하지 않은 집합이다. 모두 새 모델 검수가 필요하다는 뜻이 아니다. 기존 원문·변환 근거로 해소 가능한 항목부터 처리한다.
- 1건은 신규 initial sequence 70, grant `a8c61628-1f02-428c-b442-f0125b06064d`다. 유일한 finding은 ranking 빈 축 누락이며 note는 `정원 / 선착순 30명`이다. 영향도 기반 admission 검토 후보이지 현재 release 가능·적격·발행 완료 판정이 아니다.
- `preferred`로 추출된 조건만 문제라는 이유로 일괄 해제하지 않는다. 추출 kind 자체가 오분류일 수 있다.
- PASS 56건도 현행 source/readiness/release gate를 통과했다는 뜻이 아니다. 새 로컬 구현으로 기존 immutable 검수 PASS/HOLD 기록을 수정하지 않는다.

## 대표 사례와 최소 인수 기준

### 동작 동일 표기의 검수 오탐

신규 initial sequence 5, grant `1b674723-32e5-4b2c-a2b8-dc4c83e73447`, 서울소셜벤처허브 공고의 industry exclusion criterion 3:

- 원시 추출: `operator=not_in`, `kind=exclusion`.
- 검수: `in`으로 바꿔야 한다는 단독 needs_edit.
- 저장된 primaryMatchingProjection: 이미 `operator=in`, `kind=exclusion`.
- 현재 industry matcher는 exclusion에서 두 표기를 동일한 제외 동작으로 처리한다.

새 검수 입력은 실제 projection을 함께 제공해야 한다. 이 사례를 전체 공고의 release 통과로 확대하지 않는다. 역사 설명문을 regex로 해석하거나 모델의 equivalent 주장만으로 자동 면제하지 않는다.

### 실제 적용 범위 오류

신규 initial sequence 7, grant `1f03661c-1563-4504-bd79-bea3e4f7d2d5`, 울산 교육지원 공고 원문에는 `(신청제외 대상)-현장방문만 해당`이 있다. 트랙별 결격을 전 신청자의 공통 자격조건으로 발행하면 안 된다. 이 종류의 차단은 유지한다.

### 나머지 필수 인수

- 확정 ranking-only 지적은 해당 점수만 제외하고 suppression이 최종 발행 criteria까지 전달된다.
- 필수 자격을 preferred로 잘못 추출했거나 영향도가 unknown/누락이면 차단한다.
- 필수·제외 조건을 지운 뒤 적격으로 바뀌지 않는다.
- packet/result/aggregate/run/projection 결속 불일치와 검수 coverage 누락은 차단한다.
- 기존 PASS와 역사 reader 호환은 유지한다. 새 policy의 완전한 출력 계약을 역사 결과에 소급 요구하지 않는다.

## 구현 및 필수 검증 결과

설계·핵심 의미 인수는 `(astra-high)`, 코드·회귀 검증은 `(sol-xhigh)`가 담당했다. codebase-design 스킬의 공통 모듈 원칙을 적용해 별도 검수 레인 대신 기존 위험도 판정을 일반/launch 경로에 연결했다.

- `codex-only-v9`: 새 검수 응답은 criterion과 누락 축의 eligibility/ranking/unknown을 검증한다. legacy reader는 유지한다.
- 실제 projection과 원본 index mapping을 packet에 SHA 결속하고 검수 입력으로 제공한다. 원본 run에 snapshot이 없으면 현행 결정적 변환으로 생성·검증한다.
- 같은 reviewRisk가 launch admission과 발행 계획에 전달되고, 확정 ranking-only criterion은 실제 출력에서도 제외된다. unknown/누락/실제 자격 지적은 차단한다.
- live launch는 기존 codex-only 범위를 유지한다. dual helper의 불일치는 자동 합의로 취급하지 않는다.

`lab:release:test` 최초 실행은 실제 역사 run에 대해 held를 기대한 기존 assertion 1건에서 중단됐다. 해당 run의 완전한 primary/repair 진단에서 새 issue가 source_incomplete 하나뿐임을 확인했다. 현재 P1 판정 함수는 이번에 변경하지 않았고, 테스트에 역사 blocking counter가 양수인 채 보존됨과 source-incomplete 파생 판정의 성립을 명시한 뒤 conditional/reasons=[]를 기대하도록 수정했다. 해당 테스트 파일만 재실행해 4/4 통과했다. 이미 통과한 뒤쪽 구성요소는 다시 실행하지 않았으므로 aggregate 명령 전체의 재실행 PASS라고 표기하지 않는다.

미실행: 전체 제품 suite/build/browser, 신규 모델 실검수, DB 쓰기, launch, release prepare/approve, 배포, 개발 서버 실행. 변경은 로컬 검수·발행 계약에 한정돼 관련 통합 검증을 사용했고 무관한 전체 제품 검증은 생략했다. 새 프롬프트의 live 의미 품질·최종 서비스 노출은 이 증거로 완료를 주장하지 않는다. 기존 immutable artifact와 exact19 범위는 변경하지 않았다. 커밋은 생성하지 않았다.
