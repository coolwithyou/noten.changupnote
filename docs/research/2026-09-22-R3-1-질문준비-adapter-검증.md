# R3-1 검수 질문 준비 adapter 검증

작성일: 2026-09-22
계획 위치: `R3 — 분류된 다음 작업을 실제로 끝내기`의 첫 처리 adapter. R3-0의 exact snapshot과 처리 후 재평가 seam 위에서 `question_preparation` 한 건을 기존 승인형 promotion writer에 연결한다.

## 구현한 경계

- `grant-next-work-snapshot-v1`에 정규화한 readiness 입력과 source change impact를 함께 보존한다. 실행 직전 source/question stable key를 포함한 canonical hash, readiness, next work를 다시 계산해 snapshot 내부 변조도 adapter 호출 전에 거부한다.
- 질문 준비 adapter는 질문을 생성하거나 모델을 호출하지 않는다. 이미 사람이 검수한 manual confirmation revision이 선택된 receipt 기반 analysis-launch release만 받는다.
- 현재 B snapshot의 모든 필수 질문 stable key가 release의 v2 단일 선택·3상태·`per_notice` 질문으로 정확히 덮이는지 확인한다. source revision/raw, serving run provenance, canary 대상도 함께 확인한다.
- DB 원장의 `approved|canary_running`, manifest/release plan hash, approval artifact, aggregate/shadow/dry-run hash와 승인자/실행자 분리를 확인한다. 검증 뒤 쓰기는 새 질문 전용 SQL이 아니라 기존 promotion canary writer 포트에 위임한다.
- adapter receipt에는 before evidence, release/plan/manual selection/approval/gate/after state hash와 논리적 외부 쓰기 수를 봉인한다. 모델 호출 수는 항상 0이다.

## 격리 PostgreSQL 인수

폐기되는 전용 Unix socket PostgreSQL에 현재 원문·첨부·검수된 `industry/text_only/required` criterion과 유효한 기존 promotion을 구성했다. 질문은 없는 상태라 readiness는 B, next work는 `question_preparation`이었다.

동일 run에 결속된 수동 검수 질문 revision과 승인된 단건 canary 원장을 만든 뒤 기존 `createDrizzlePromotionPort`로 적용했다. 적용 뒤 다음을 확인했다.

- 기존 criterion ID 유지
- 활성 `confirmation-evaluation-v2` 질문 1건 생성
- 질문의 current source revision/raw와 `per_notice` scope 유지
- 새 promotion item의 after snapshot과 현재 DB state 일치
- readiness B → A, next work `question_preparation` → `reuse_ready`
- 모델 호출 0회

이 fixture는 실제 사람의 결정을 만들거나 운영 release를 승인하지 않는다. 운영 DB, 모델 provider, 외부 네트워크를 사용하지 않았다.

## 검증 명령

- `pnpm --filter web typecheck`
- `pnpm test:grant-product-readiness`
- `pnpm test:product-postgres`

## 남은 경계

- 실제 질문 후보는 기존 review/draft/manual selection/release prepare·gate·approve 절차에서 만들어져야 한다. adapter 자체가 draft를 승인 자산으로 바꾸지 않는다.
- 실제 서비스 DB 적용과 exact 샘플 이관은 R5의 별도 쓰기 승인 대상이다.
- 다음 단계는 R3-2다. 의미 불변 `evidence_refresh`만 source rebind하고 조건·coverage 변경은 검수 작업으로 보존한다.
