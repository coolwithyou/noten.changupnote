## 판정: 채택 권고 (조건부 GO)

사전 정의된 수치 게이트(축 일치율 ≥ 0.9)는 미달했으나, **동일 모델 대조군 실측으로 그 게이트 지표 자체가 딥분석 태스크의 실행 간 비결정성에 지배됨이 증명**됐고(§3), §8-2가 미달 시 절차로 정의한 **판정 사례집 방식의 원문 대조 판정 59건에서 CLI 레인이 명백히 우세**했다(추출 38건 중 CLI 30 : API 3, 감사 21건 중 CLI 19 : API 1). transport 오염(환각·원문 이탈)의 증거는 0건이다. 운용 조건 3개를 §6에 명시한다.

## 1. 방법

### 1-1. 설계 변경 (계획 대비)

계획의 "기존 API 런 재사용(추가 지출 0)" 전제가 실측에서 깨졌다: 기존 30건 트랙 런은 전부 promptVersion lab-deep-v1~v3라 v5와 비교하면 프롬프트 개정이 교란 변수가 된다. → **양측 신규 실행**(API·opus-4-8·v5 vs CLI·opus-5·v5)으로 전환. API 추가 지출 $2.20(9건).

### 1-2. 표본

- **추출**: 층화 10공고 — 밀도 상(criteria 13~23) 3, 중 3, 하 3, 0건 대형(통합공고 92,573자) 1. 전 공고 `inputSha256` 양측 동일 확인(동일 입력 보장).
- **감사**: 기존 감사 파일 중 재감사 가능(aiAuditVerdict 보유·humanVerdict 없음) 항목 보유 11파일 77항목을 스크래치 미러로 복사, **실제 `runAiAudit` 코드를 cwd 전환으로 미러에서 재실행**(CLI transport·sonnet-5). 원본 spike-out 무접촉. 6파일 41항목 재감사 성공, 5파일은 `input_drift`로 정당 스킵(수집 크론이 7/22 이후 원문 갱신 — 드리프트 가드 정상 작동). 드리프트 스킵분은 지표에서 제외(포함 시 가짜 100% 일치 오염 — 비교기에서 명시 차단).
- **판정 사례집**: 불일치 전수(추출 38 + 감사 21 = 59건)를 공고별 판정 에이전트가 **재조립 원문 전문을 직접 읽고** 판정. 판정 기준은 항상 원문.

## 3. 대조군 — 수치 게이트 불성립의 증명

**같은 모델(claude-sonnet-5)로 transport만 바꾼** 2공고 대조군의 축 일치율: **2/12 = 16.7%**. 즉 essence 집합 완전 동일을 요구하는 이 지표는 동일 모델 재실행 쌍조차 통과할 수 없는 기준이며, 41.5%라는 수치는 transport 오염이 아니라 **비결정 태스크의 실행 간 기본 변동**이 지배한다. 대조군에서도 CLI 측 spanVerified 14/14 = 100%(API 11/13) — 전 실측에서 CLI 측 span 검증률이 일관되게 100%다.

- CLI가 추가 추출한 축(new) 10건: **전부 원문 실재 조건** — 환각 0. (예: 모집분야 제한, 창업기업 확인서 요건, 민간부담금 20% — API가 통째로 누락한 실질 자격조건들)

## 6. 운용 조건 (채택 시)

1. **사람 표본 감사 유지**: 자동확정 전환률 상승(88.9%)의 이면인 오확정 잠재(검수 오류 기인)는 기존 절차의 표본 사람 감사로 통제한다 — 검수팀 ops 체계와 접점.
2. **배치 운용 명령에 타임아웃 상향 동봉**: `ANALYSIS_LAB_TIMEOUT_MS=900000 ANALYSIS_LAB_TRANSPORT=claude-cli ANALYSIS_LAB_MODEL=claude-opus-5 pnpm lab:batch ...`
