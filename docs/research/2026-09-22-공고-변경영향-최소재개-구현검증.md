# 공고 변경 영향·최소 재개 구현 검증

## 구현 범위

- 수집 publisher가 이전 snapshot을 덮어쓰기 전에 현재 입력과 비교한다.
- 비교 범위는 `raw`, 모집 기간·상태, eligibility projection, 원문 coverage, 첨부, 추출 계약으로 분리한다.
- 결과는 `grant-source-change-impact-v1` 영수증으로 현재 raw hash와 같은 `grant_collection_events` 행에 저장한다.
- 준비도와 matching campaign은 같은 영수증을 읽어 다음 최소 작업을 선택한다.

| 변경 | 다음 작업 | 모델 실행 |
| --- | --- | --- |
| 조회수·관측 메타데이터만 변경 | `source_rebind` | 없음 |
| 접수 기간·모집 상태만 변경 | `recruitment_refresh` | 없음 |
| 조건 projection·추출 계약 변경 | `condition_review` | 없음 |
| 새 제외 조항·참조 첨부 변경 | `coverage_review` | 없음 |
| 과거 영수증 없음·지원하지 않는 수집원 | `source_change_review` | 없음 |

`analysis_missing`만 기존과 같이 모델 분석 후보가 된다. 변경 영향 검토 결과 자체는 모델 실행 권한을 만들지 않는다.

## 안전 경계

- K-Startup coverage는 실제 분석 입력에 포함되는 신청대상, 제외대상, 우대, 업력, 연령, 지역, 지원분류, 공고 본문과 상세 참조 구역을 봉인한다.
- Bizinfo coverage는 지원대상, 지원분야, 신청방법·서류, 사업요약, 해시태그를 봉인한다.
- 참조 첨부 inventory가 달라지면 원문 문구가 같아도 coverage 검토로 보낸다.
- 알 수 없는 수집원이나 손상된 영수증은 자동 재사용하지 않는다.
- migration 이전 이벤트는 `change_impact = NULL`로 유지한다. 이전 payload를 추정 복원하지 않고 기존 원문 변경 검토에 남긴다.
- 이벤트의 `(source, source_id, raw_hash)` 고유키를 그대로 사용해 같은 수집 revision의 반복 기록을 막는다.

## 아직 실행하지 않은 단계

- migration 적용
- 기존 이벤트 backfill
- 배포와 production 수집 1회 후 실제 `change_impact` 분포 확인
- `source_rebind`, `recruitment_refresh`, `coverage_review`를 처리하는 운영자 작업 표면

이번 변경은 분류·저장·공용 후속 작업 판정까지 구현한다. DB 쓰기와 배포 없이 로컬 코드·migration 후보만 검증했다.
